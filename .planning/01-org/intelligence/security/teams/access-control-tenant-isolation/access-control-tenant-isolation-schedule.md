# Access Control & Tenant Isolation — Schedule & Skills

## Recurring work

| Cadence | Job | Emits |
|---|---|---|
| **Per PR** | `scripts/check_endpoint_guards.sh` — controller has a guard, or the route is on the allowlist. **Does not exist; ships red with 94 entries** | Pass/fail; `sec.unguarded_authenticated_surface` |
| **Per PR** | `@Public()` allowlist diff — first decorator outside the known set escalates | `sec.public_decorator_count` |
| **Per PR** | Tenant-derivation check — flag a guarded `/:restaurantId` handler with no ownership assertion | `sec.guarded_routes_with_url_tenant` |
| Weekly | New-controller audit — every controller added since last run, classified before merge where possible | Verdicts; allowlist diff |
| Weekly | L-ACT-1 burn-down; L-ACT-2 two-number report; L-ACT-3 derivation audit | [[access-control-tenant-isolation-agenda-board]] refresh |
| Weekly | Classification sitting — one module per session, verdict template filled | `sec.routes_classified` |
| Quarterly | L-ACT-4 verdict review with [[red-team-charter]] | `sec.verdicts_reversed` |
| Quarterly | Charter staleness sweep (foundation §3.3, §6) | Archive or revision |

**Anti-sprawl applied honestly.** The **weekly classification sitting is designed to
delete itself**: it exists to drain 94 routes and has no steady-state purpose. When
`sec.routes_classified` = 94 it is removed, not renamed. The per-PR checks are the only
entries here meant to outlive the campaign — everything else is campaign scaffolding, and
labelling it as such now prevents it becoming a standing meeting that produces no action
(foundation §6's 3-run rule).

**The one job that must survive the split.** After this team divides from
[[perimeter-ingress-integrity-charter]], the weekly new-controller audit stays here. It is
the entire steady-state charter: something has to read every new controller, forever, or
instance #5 arrives.

## Skills owned

Skills live in `.claude/skills/`. A skill unfired for 30 days is reviewed for deletion.
The registry is [[skills-charter]]'s (Applied AI); we author, we do not govern.

Two skills, each with the real past instance foundation §3.3 demands. Both are **proposed,
not built** — the repo has exactly one project skill today.

### `endpoint-guard-census`

- **Trigger.** Per PR touching `apps/api-gateway/src/**/*.controller.ts`, and weekly.
- **Doneability.** Emits two numbers — unguarded-reachable and `@Public()` count — plus a
  diff against `.security/endpoint-allowlist.txt`. Fails the build when a route is
  unguarded and unlisted. **Producing one number without the other is a failed run**, not a
  partial success.
- **Real past instance.** The `/analytics/consult` denial-of-wallet hole sat across 39
  routes and survived ordinary review until `ENDPOINTS.md` was generated by a scan. Nobody
  had ever produced the list; the exploit was two `curl` calls. This skill is that scan,
  on a schedule.
- **Owner.** This team. **Scheduled:** yes, per-PR + weekly.

### `route-classification-pass`

- **Trigger.** Any route appearing in the census without a verdict; any new controller.
- **Doneability.** A completed five-field verdict per route
  ([[access-control-tenant-isolation-agenda-full]]), with `consumer` named and backed by a
  `path:line`. **`unknown` returns an escalation, not a verdict** — a skill that emits
  `unknown` and exits has failed.
- **Real past instance.** Two module-level misclassifications in the repo's own census:
  `vendor-portal` was labelled *"webhook module — must verify signatures"* when it is
  public content by slug (since corrected), and `simpos` is *still* labelled a webhook
  module when it is an unauthenticated simulator control surface whose `close` route makes
  our own server sign a stock movement (`simpos.service.ts:489-520`). Per-module judgment
  has been wrong twice out of five ingress modules.
- **Owner.** This team. **Scheduled:** weekly during the campaign; per-PR after.

### Deliberately not proposed

- **`auto-guard-fixer`** — a skill that adds `@UseGuards` automatically. It would optimise
  the exact metric [[access-control-tenant-isolation-premortem]] M3 says is blind: it
  cannot tell whether the tenant comes from the token, and it would drive the census to
  zero while leaving cross-tenant access live. The classification is the judgment; the
  decorator is the trivial part. Automating the trivial part is how the number stops
  meaning anything.
- **`rls-policy-generator`** — premature. Whether RLS is a control on the gateway path at
  all is an open question (`database.service.ts:15` uses the service-role key). Generating
  policies before answering that produces 182 more statements nobody relies on.
