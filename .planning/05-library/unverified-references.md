## The rule for getting off this page

An item leaves this note only when **both** hold:

1. **Identity is confirmed** — by the founder supplying the URL, or by a verified fetch that
   matches the description. A plausible search hit is not confirmation.
2. **It is evaluated against a named need that already exists** — per
   `.planning/01-org/commercial/media-brand/media-brand-agenda-full.md`: *a shortlist is not
   a stack.*

At that point it gets its own note with `status: candidate` and the same sections every
other entry carries.

## Why this page will not be quietly cleaned up

The tempting move is to guess: search each name, pick the best-looking match, and write it
down as fact. Several of these would produce a confident-looking wrong answer — "Jules" and
"Jackie Zhang" especially. The corpus has already been damaged once by
repeated-but-unchecked claims (see the loop-frontmatter and department-count corrections in
`.planning/foundation/ORG_STRUCTURE.md`). Eight honest blanks are cheaper to fix than one
wrong entry that everything downstream then cites.
