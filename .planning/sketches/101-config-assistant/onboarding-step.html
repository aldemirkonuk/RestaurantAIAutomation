03

The skip is the actual proposal

what is broken today, in one measurement
Today
“Skip for now” writes nothing at all.

ThresholdStep.tsx:80–81 calls onDone() and returns. The only state it could have touched is restaurants.threshold_configured boolean DEFAULT false NOT NULL (baseline :3597) — which is false for a house that skipped and for a house nobody ever asked.

The product cannot tell them apart. That is absence reported as health at the front door of onboarding: the register later shows an em dash and cannot say whether the silence was a choice.

Proposed
An explicit skip writes one row, and changes no setting.

The asking is a fact. Recording it costs one insert into a table that has existed since the baseline, and no migration. Nothing about the values changes — every default stays exactly where it was.

Then the assistant can say “you skipped this on 4 September — want to set it now?” instead of “nobody has ever set this”, which is a different and worse sentence to hear about your own restaurant.

One blocking precondition, and it is not cosmetic. The ceiling question ships after that gate, or not at all.

07

Two things this drawing is asking

and one it is deliberately not asking
QuestionWhy it is open
Five questions, or three?Today it is one. Five in one sitting is still one screen, but the vendor-cutoff question repeats per vendor and a house with eight vendors would feel it. The alternative is to ask it once for the vendor they order from most and leave the rest to /settings.
Should “Talk it through” exist here at all?It routes into the assistant of the conversation. That is the founder’s bigger ask arriving at the earliest possible moment — before the owner has any feel for the product, which is either the best time or the worst.
Not asking: whether to keep the defaults.That was already decided — “keep as defaults, but while onboarding they have the option to do that.” Every default in the code stays exactly where it is. This screen changes only whether anybody was asked.
