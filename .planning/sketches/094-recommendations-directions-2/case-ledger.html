A case only leaves Acted for Watching when something is set to measure it — which is exactly what Make this a goal does. That is the shape of this direction: the goal button is not a side door, it is the instrument that lets a case close with a number.

Refused is a state, not a bin. Four cases were dismissed with a reason, and the reasons are the taxonomy: already handled ×2, I disagree ×1, not relevant ×1. Google suppresses; AWS excludes; neither keeps the reason where the rule can be judged by it.

What this direction needs that does not exist

proposed A case store. Today the page has dispositions (recommendation_actions: dismissed / snoozed / done / pinned / acted) which is four-fifths of a state machine already — what is missing is watching and a closing reason, both of which Stripe Radar models exactly (review.opened / review.closed with a reason).
proposed The outcome measurement. Nothing anywhere in the gateway measures what happened after an entry was ruled off. It is a scheduled job over the same engine, and it is the single largest piece of work of the three directions on this page.
proposed The goal → case join. analytics_goals has no column naming the recommendation a goal came from, so the built button can say “you already track this figure” and can never say “this case is being watched”. One nullable column closes it; it is a migration and a founder’s call.
Google Search Console is the closest working model of this lifecycle in any product — an issue is detected, you fix it, you request validation, and it passes or fails per URL and then closes; and it stays closed for 90 days before the same fault counts as new.
