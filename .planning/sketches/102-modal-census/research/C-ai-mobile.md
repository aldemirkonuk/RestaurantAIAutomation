# C — AI-native and mobile overlay behaviours (SOTA scan)

Angle: AI-native and mobile behaviours, for Mudavym's overlay policy (ADR 0112: SHEET 440/640 for one object,
PANEL 620 for a question/confirmation, POPOVER 320 for a choice/menu; wax-seal hold-to-approve for real
commitments, never in a popover; close is words not X; "the assistant proposes, the seal applies" — ADR 0113;
"a draft never looks sent"; an absence is reported as an absence, never a zero).

Every row below is evidence-first: a product, a URL, and the concrete behaviour as documented. Anything not
confirmed against a primary doc is flagged inline as **[unverified: ...]** — it is included because it is
useful signal, not because it is confirmed fact.

## 2. The proposal panel — how the best products show an AI proposal a person applies

**1. GitHub Copilot Edits (Visual Studio)** — the most fully worked-out version of "diff shown, accepted hunk by hunk, then applied." Per Microsoft's own docs, the review experience explicitly separates three granularities: *"Across all files at once by using the global accept/undo controls, per file by using the controls next to each file header, or per individual diff chunk by using the inline accept/undo buttons."* Crucially, it also keeps a **checkpoint history** — "Tracks all changes (proposed, accepted, dismissed, and manual edits) made to the file" — so a rejected or reverted proposal is not simply gone. [learn.microsoft.com/en-us/visualstudio/ide/copilot-edits](https://learn.microsoft.com/en-us/visualstudio/ide/copilot-edits?view=visualstudio)

**2. Cursor's persistent diff/approval mode** — the file stays in a reviewable state until every hunk is resolved, and community bug reports about it auto-applying or not exiting cleanly are useful *negative* evidence: an ambiguous proposal state is a real failure mode users notice and complain about. [forum.cursor.com](https://forum.cursor.com/t/regression-ai-edits-applying-automatically-without-diff-approval-ui/154887)

**3. ChatGPT Canvas's "Show changes"** — a single clock-icon toggle renders the delta between the current and prior draft as strikethrough-red / highlight-green, and a **Restore this version** action sits directly below it. This is the cleanest precedent for treating an AI-touched document's *history*, not just its current diff, as something the person can always get back to. [help.openai.com/en/articles/9930697](https://help.openai.com/en/articles/9930697)

**4. Notion's Suggested Edits** — the most important structural idea in this whole section: a suggestion is its own layer *on top of* the document, not an already-applied change waiting to be undone. Hovering exposes ✔️ accept or ❌ reject per suggestion, and nothing is touched until one of those fires. [notion.com/help/suggested-edits](https://www.notion.com/help/suggested-edits)

**5. Claude Artifacts' branch-on-edit** — editing an earlier turn doesn't mutate the current artifact state; it forks a new version with its own history. Good for auditability, but only if the fork is visibly labelled — an invisible fork is worse than no fork. [support.anthropic.com/en/articles/9487310](https://support.anthropic.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them)

**6. Perplexity's citation-during-generation** — citations aren't retrofitted after the answer is drafted; per Perplexity's own cookbook, "the LLM tracks information origins from selected documents, attaching inline citations to each statement" as it writes, and this can stream to the client incrementally. Applied to Mudavym, a proposal panel that streams should stream its sources with it, not append them at the end. [docs.perplexity.ai/docs/cookbook/articles/streaming-citations/README](https://docs.perplexity.ai/docs/cookbook/articles/streaming-citations/README)

**7. Granola's black-vs-gray provenance** — the single strongest precedent for "nothing is invented to fill a gap": the person's own words and the AI's additions are never visually merged into one undifferentiated color, even after the note is "final." [docs.granola.ai](https://docs.granola.ai/help-center/getting-started/granola-101)

**8. Linear Agent's queue-while-working, but never self-resolve** (the cautionary case) — Linear lets its agent "resolve and unresolve comment threads" on its own initiative. That's the one behaviour in this whole research pass that a straight port would break ADR 0113 outright: Mudavym's assistant may gather evidence and queue a proposal while working, but must never be the one that marks its own proposal done. [linear.app/changelog/2026-03-24-introducing-linear-agent](https://linear.app/changelog/2026-03-24-introducing-linear-agent)

## 3. The phone at the door — bottom sheets, detents, swipe-to-commit, offline

**1. Apple's detents (`.medium` / `.large` / custom fraction or height)** — a sheet has "particular heights at which a sheet naturally rests," and the grabber (drag handle) shows itself automatically only when more than one detent is configured — otherwise it's hidden by default. Confirmed via a direct HIG quote captured by a secondary source: *"A resizable sheet expands when people scroll its contents or drag the grabber, which is a small horizontal indicator that can appear at the top edge of a sheet."* [createwithswift.com](https://www.createwithswift.com/exploring-interactive-bottom-sheets-in-swiftui/) quoting [developer.apple.com/design/human-interface-guidelines/modality](https://developer.apple.com/design/human-interface-guidelines/modality)

**2. Apple's dismissal rule, stated as a design principle, not just a mechanic** — "Provide an obvious and safe way to exit a modal task. Make sure people always know the outcome of their action when they dismiss a modal view." (HIG modality guidance, via mirror) [codershigh.github.io](https://codershigh.github.io/guidelines/ios/human-interface-guidelines/interaction/modality/index.html) — this is effectively the same instinct behind Mudavym's own "close is words, never an X" rule, independently arrived at.

**3. Android's standard vs. modal bottom sheet** — a **standard** sheet "operate[s] independently to (and allow[s] for simultaneous interaction with) primary screen content" and can be collapsed, expanded, or hidden; a **modal** sheet blocks the rest of the screen. This is a real, named distinction Mudavym does not currently have — a non-blocking sheet is a materially different object from ADR 0112's SHEET. [m2.material.io/components/sheets-bottom/android](https://m2.material.io/components/sheets-bottom/android)

**4. Uber/Lyft's persistent sheet-over-map** — one sheet component carries an entire flow (destination entry → matching → en route → arrived → in trip → completed) by changing its own content and height rather than pushing new screens. Lyft's own team is on record choosing native OS sheet conventions over their internal design system's own component for exactly this surface, because platform-native muscle memory beat visual consistency. [designsystems.com](https://www.designsystems.com/a-system-built-on-parity-how-to-treat-all-of-your-users-equally/)

**5. Robinhood's review-then-swipe-up, with haptic feedback during processing** — the closest documented match to the founder's explicit swipe-up-to-accept ask; Robinhood's own support copy describes "gentle vibrations" as taptic feedback plays while an order processes. [robinhood.com/us/en/support/articles/selling-a-stock](https://robinhood.com/us/en/support/articles/selling-a-stock/)

**6. Apple Pay's double-click + biometric + Secure-Enclave signing** — not a sheet at all, but the single best evidence for what a *seal* should feel like: a deliberate gesture, biometric-grade confirmation, and a cryptographic binding to the one specific transaction rather than a generic "yes." [support.apple.com — Apple Pay payment authorization](https://support.apple.com/en-asia/guide/security/secc1f57e189/web)

**7. WhatsApp's offline queue and tick vocabulary** — a message composed with no connection can still be sent; it holds locally and dispatches automatically on reconnect, visualized through an explicit state ladder (clock → single grey tick → double grey → double blue) that never lets "queued" be confused with "delivered," let alone "read." This is the clearest available template for "saved on this phone" states inside a receiving-door or cellar-register overlay. [phonearena.com — offline messages queue](https://www.phonearena.com/news/WhatsApp-brings-offline-messages-queue-feature-on-iOS-redesigns-storage-usage-screen_id90340) **[tick semantics and offline-queue mechanics are documented by tech press / community sources, not Meta's own published spec]**

## 4. Top 8 for Mudavym — ranked

1. **Notion's Suggested-Edits layer (#9)** — the single best structural fix for "a draft never looks sent": an AI proposal renders as an overlay *on* the record, never as an already-mutated cell, until a person disposes of it one way or the other.
2. **Apple Pay's double-click + biometric + transaction-bound signing (#22)** — the clearest available model for what the wax seal should *mean*, not just look like: a deliberate gesture cryptographically tied to the one specific commitment.
3. **Robinhood's review-then-swipe-up with haptic feedback (#20)** — the literal mechanic the founder asked for, already proven at scale in a high-stakes financial app; needs Mudavym's own stamp-completion payoff layered on top.
4. **Granola's black-vs-gray provenance (#16)** — directly operationalizes "nothing is invented to fill a gap" as a permanent visual rule, not just a pre-accept state.
5. **GitHub Copilot Edits' three-level accept granularity + checkpoint history (#1)** — the most complete diff-and-apply model in the scan; its checkpoint history (proposed/accepted/dismissed/manual, all tracked) is exactly the audit trail CLAUDE.md's "every decision gets a record" instinct wants.
6. **ChatGPT Canvas's scoped inline edit + Show-changes + Restore (#6)** — best fit for Communications/vendor-letter drafting: narrow the AI's touch to a highlighted passage, show the delta plainly, keep every version reachable.
7. **WhatsApp's offline queue + tick ladder (#24)** — the right vocabulary for the door on a phone: a receiving-door entry made with no signal must look provisional (queued) and only ever step forward through explicit, unmistakable states — never silently read as confirmed.
8. **Perplexity's citation-during-generation (#15)** — makes "sources shown with the answer" a default of the assistant's proposal panel itself, streamed live rather than appended after the fact, which is the most direct fit for "an absence is reported as an absence."

**Flagged as genuinely open forks, not defaulted:** a non-blocking "standard" sheet distinct from ADR 0112's three shapes (#19, Android Material); true drag-resizable detents on mobile (#18, Apple HIG); a global "anywhere" quick-entry capture mode (Things 3 / Todoist, referenced in §1 rows 11 and 18–19's surrounding discussion) — each would add to the locked overlay taxonomy and belongs in `.planning/decisions/OPEN-DECISIONS.md` before being built.
