# B — Ops & Finance SOTA Overlays: records, approvals, receipts, ledgers

Angle: operations/data/finance products where the object of work is a **record**, a
**decision**, or a **money movement** — closest analog to Mudavym's orders, receiving,
inventory ledger, cellar, vendors, letters, team schedule, reports. Every row below
cites a real URL (docs, help centre, changelog, or a named reputable teardown). Where a
search could not surface a primary-source confirmation, it is marked **UNVERIFIED** in
the behaviour cell rather than asserted as fact.

Mudavym's locked shapes for reference (ADR 0112): **SHEET** (440/640px, right, one
object) · **PANEL** (620px, centred, a question/confirmation) · **POPOVER** (320px,
anchored, a choice/control menu) · seals use hold-to-approve "wax," bulk uses a plain
button, the seal never sits in a popover, close is words not an X, AI proposes/person
applies, a draft never looks sent, every figure names its rows, ledger rows expand in
place.

## 4. Top 8 for Mudavym (ranked)

1. **Two-checkpoint money ceremony (approve, then release)** — Ramp's split between chain-approval and payer-release is the cleanest primary-source validation that "approving an order" and "approving a payment" should be two separate wax seals, exactly as ADR 0112 already lists them.
2. **Hard system-enforced separation of duties** — Mercury's initiator-excluded-from-approvers rule turns Mudavym's "two-person rule" idea (if the founder wants one) from a UI suggestion into a system guarantee; worth an explicit ADR of its own given how concretely Mercury has already solved it.
3. **In-place two-column invoice-vs-order compare** — Ramp's OCR-suggested PO match plus Restaurant365's cell-level flagged discrepancy view is the single closest real-world match to the founder's "side-by-side compare inside an overlay" ask, and both do it in-place rather than in a popup — directly compatible with "ledger rows expand in place."
4. **"Why this was flagged," written on the row** — Ramp's inline policy-violation reasoning is a one-line addition to Mudavym's existing provenance discipline: every flag should name the rule it tripped, the same way every figure already names the rows it summed.
5. **Bulk-select bar with full keyboard parity, Esc-clears** — Linear's model (X to toggle, Shift-range, Cmd/Ctrl+A, Esc clears, bottom bar plus Cmd K for the long tail) is a ready-made keyboard spec to adopt verbatim for Mudavym's list views, not just a visual bar to imitate.
6. **Split state: "delivered" is not "received"** — Lightspeed's Draft/Placed/Delivered/Received progression, with Toast's "mark as received flips inventory in the same click," together argue Mudavym's receiving flow needs an explicit arrived-but-unreconciled state distinct from the final ledger-affecting one.
7. **Tiered undo: instant Cmd+Z, then a cold-storage window** — Linear's two-layer safety net (system-wide undo, then a 30-day recovery archive) is a stronger and cheaper-to-build model than a single 5-second toast, and it composes with Mudavym's existing "no shortcuts" ethic around irreversible actions.
8. **Camera-at-the-door, review-on-a-bigger-screen** — Toast's own guidance that phone capture is fine but review belongs on desktop is a permission Mudavym should take explicitly: `receiving-door.md` should optimize for fast capture and a coarse accept/flag, and defer detailed line-item reconciliation to `receiving.md`.
