# A — Command-first, keyboard-first overlay research

Angle: Linear, Raycast, Superhuman, Warp, Arc, Vercel, GitHub, Height (defunct),
Notion Calendar (Cron), Slack, Figma. Evidence-gated: every pattern below carries
a URL. Where a claim could not be confirmed from a primary source it is marked
**unverified**.

Mudavym's locked shapes (ADR 0112) for reference throughout: **SHEET** (440/640px,
one object), **PANEL** (620px, a question/confirmation), **POPOVER** (320px, a
choice/control menu). Real commitments seal with hold-to-approve "wax"; bulk gets
a plain button; the seal never sits in a popover; close is words, never an X;
AI proposes, a person applies; a draft never looks sent; ledger rows expand in
place.

## 1. Pattern table

| # | Pattern | For (object / question / choice / in-place / anywhere) | Product + evidence | Concrete behaviour | Mudavym surface + how | Risk / conflict with house rules |
|---|---|---|---|---|---|---|
| 1 | **Peek preview beside the list** | in-place (object, ephemeral) | Linear — [Peek preview docs](https://linear.app/docs/peek) | `Space` toggles peek on/off (hold to preview temporarily, release to close); `↑`/`↓` move to the adjacent issue/project while the preview updates live; `Esc` closes; peek "can only be launched with the keyboard" — no mouse trigger exists. | `/orders`, `/inventory`: peek a line item or PO from the list without leaving it, stepping with arrows to the next line. | Peek is a fourth overlay shape — not SHEET/PANEL/POPOVER. Either it must be re-classed as a lightweight SHEET variant (no wax, no close-by-X) or it's a new shape needing its own ADR fork. |
| 2 | **Keyboard stepping inside an open record** | object | Linear — same [Peek docs](https://linear.app/docs/peek); Superhuman — [navigation shortcuts](https://nickgray.net/superhuman/) confirm `J`/`K` move to next/previous conversation, `Enter` opens it | Arrow/`j`/`k` move between sibling records while a detail surface stays open; the surface's content swaps, position doesn't. | A `/orders` or `/providers` SHEET: once one PO/vendor is open, `j`/`k` steps to the next without closing and reopening the sheet. | None structural — this is purely a keybinding inside the existing SHEET; must confirm it doesn't collide with the shell's own `j`/`k` if reserved elsewhere. |
| 3 | **Command menu with nested, non-firing sub-menus** | choice | Linear command menu — described in [How to Use Linear's Command Menu](https://www.storylane.io/tutorials/how-to-use-linears-command-menu) and corroborated by shortcut references ([fastshortcuts.com](https://fastshortcuts.com/shortcuts/linear/)) | Typing a command with children (e.g. assign) drills into a sub-list instead of firing; `Backspace`/`Esc` steps back one level rather than closing outright. | The shell's `⌘K`: "Assign vendor to…" or "Move to…" drills into a picker instead of needing a separate POPOVER. | Must keep the "Esc = one level back, not full close" behavior distinguishable from the house rule that Esc/word-close dismisses a shape entirely — needs its own stated Esc contract. |
| 4 | **Typed arguments inside the command itself** | choice → object | Raycast — [Arguments docs](https://developers.raycast.com/information/lifecycle/arguments) | A command can declare up to 3 arguments (`text`, `password`, `dropdown`) filled in directly in root search before the command runs; required arguments must precede optional ones; values are typed via a generated `Arguments` interface. | `/providers`: `⌘K → "email vendor" → [vendor dropdown] [amount text]` fires a pre-filled draft without a separate form screen. | Good fit for POPOVER-scale choices, but a 3-argument command risks becoming a disguised form — must stay reachable as a true one-shot pick, not a multi-field submission (which belongs in a PANEL/SHEET, not a command). |
| 5 | **Single-letter + g-chord navigation grammar** | anywhere | Linear — shortcuts summarized in [fastshortcuts.com/shortcuts/linear](https://fastshortcuts.com/shortcuts/linear/) (`G` `I` inbox, `G` `P` projects, etc.), corroborated by [Linear's shortcuts help changelog](https://linear.app/changelog/2021-03-25-keyboard-shortcuts-help) (`?` opens a searchable shortcut sheet) | Two-key chords (`g` then a letter) jump to a named view instantly; `?` opens a live-searchable shortcut reference from anywhere. | The shell: `g o` → `/orders`, `g i` → `/inventory`, `g c` → `/cellar`, etc.; `?` opens Mudavym's own shortcut sheet. | None — this is a pure navigation layer, orthogonal to the overlay shapes; but reserves letters that a POPOVER's own single-key actions must not collide with. |
| 6 | **Undo toast replaces a confirm dialog** | in-place / question, replaced by notification | Linear — [Undo actions changelog](https://linear.app/changelog/undo-actions) | `⌘Z` (or typing "Undo" in the command menu) reverses "almost every operation that changes issues, notifications, cycles or projects," including bulk edits across hundreds of rows; `⇧⌘Z` redoes; the user is returned to the page the action happened on with the affected rows re-selected. | `/inventory`, `/orders`: a bulk status change or delete fires immediately with an undo toast instead of a PANEL confirmation — for **reversible** ops only. | Direct tension with "a real commitment is sealed with wax": undo-instead-of-confirm is only safe for actions that are actually undoable server-side (status/label changes), never for a vendor-facing send or a financial commit — must be scoped explicitly per action type, not applied globally. |
| 7 | **Undo send (delayed commit, not true recall)** | question, replaced by a delay window | Gmail — [official Gmail blog, "How to undo send"](https://blog.google/products/gmail/how-to-unsend-email-gmail/) | Clicking Send queues the message for a configurable 5–30s window; "Undo" during that window pulls it back to Drafts; past the window it is genuinely gone and unrecoverable — it is a delayed-send buffer, not a retraction. | `/communications`: sending a letter to a vendor queues for ~10s with an inline "Undo" before it actually leaves. | Interacts with "AI proposes, a person applies" and "a draft never looks sent" — the queued state during the undo window must visibly read as "about to send," not as "sent," or it silently breaks the draft-vs-sent contract. |
| 8 | **Natural-language input resolved inline (no date picker)** | in-place, inside a SHEET/PANEL field | Superhuman Command — [Superhuman Command announcement](https://new.superhuman.com/superhuman-command-29123); phrasing corroborated by third-party coverage of "in 2 weeks," "next Thursday at 3pm in Australia" | A text field parses relative/absolute natural language (including cross-timezone) and resolves it into a concrete timestamp shown back to the user before commit; a dedicated `H` key jumps straight to "Remind me" without opening Command first. | `/calendar`, `/communications`: a follow-up field takes "next tue 3pm" and resolves to a real date+time chip inline. | Parsing ambiguity is real risk (wrong date silently accepted); the resolved value must render as an explicit, editable chip — not swallowed into free text — so a misparse is visible before commit. |
| 9 | **Fuzzy command-name matching, not exact strings** | choice | Superhuman Command — [announcement](https://new.superhuman.com/superhuman-command-29123): "enter just a few characters for what you want" (e.g. "sen" → Sent Mail, "sn" → snooze), shortcuts shown inline to teach the full bind over time | The palette accepts partial/abbreviated input and ranks by fuzzy match; each result also displays its direct keyboard shortcut, so the palette doubles as a shortcut-teaching surface. | The shell's `⌘K`: typing "rec" surfaces "Receiving," "Recent orders," etc.; each row shows its own hotkey to teach it. | None structural; only cost is maintaining a good fuzzy-match/ranking function as the command set grows past a few dozen entries. |
| 10 | **Full keyboard-only completion of a triage flow** | anywhere (a whole workflow, not one overlay) | Superhuman Split Inbox — surfaced via search of [help.superhuman.com "Achieve Inbox Zero"](https://help.superhuman.com/hc/en-us/articles/46005833597709-Achieve-Inbox-Zero) (per-item triage keys `J`/`H`/`E` for today/later/done; next item auto-selects; ends at zero) | Triage keys act on the current item and immediately auto-advance to the next, so a whole inbox can be cleared without ever touching the mouse or reopening a list. | `/notifications`: triage every notification (snooze / act / dismiss) via three keys with auto-advance to zero unread. | Auto-advance must not silently apply an action a user didn't mean to confirm — needs the same undo-toast safety net as row 6 for anything non-trivial. |
| 11 | **Quick-capture overlay callable from outside the app entirely** | anywhere | Raycast Notes ("Floating Notes") — [official announcement tweet](https://x.com/raycastapp/status/1599070998321471489): "stays on top of all windows... recommend toggling it with a hotkey, e.g. ⌥N" | A global OS-level hotkey summons a small floating capture window regardless of which app has focus; it stays pinned above other windows until dismissed. | The shell: a global hotkey opens a small "quick note / quick follow-up" capture reachable even when Mudavym isn't the focused browser tab (via a PWA shortcut or similar). | Web apps can't truly register an OS-wide hotkey outside their own tab without a PWA/extension — this pattern's "anywhere" claim only ports partially to a web SPA; flag as a platform limitation, not a design one. |
| 12 | **Deep-linkable commands (URL triggers an app action)** | anywhere, addressable | Raycast — [Deeplinks docs](https://developers.raycast.com/information/lifecycle/deeplinks) and [createDeeplink](https://developers.raycast.com/utilities/functions/createdeeplink): `raycast://ai-command/<slug>` launches a specific command from outside Raycast; copyable via `⌘K → Copy Deeplink` on any command | Every command (including AI commands) has a stable, shareable URL that reproduces the exact invocation; deeplinks can be handed to another user, a script, or a keyboard tool. | `/settings`, the shell: every saved view, report, and command has a URL that reopens the *same* overlay state — e.g. a deep link straight into "receiving door: item 4021 peek open." | Requires overlay open/closed state to live in the URL (query param or path segment) for every SHEET/PANEL/POPOVER — real engineering cost, and must not deep-link into a state that looks "sent" when it's a draft. |
| 13 | **Command palette with typed scope sigils** | choice, disambiguated by prefix | GitHub — [Command Palette beta changelog](https://github.blog/changelog/2021-10-27-command-palette-beta/): `>` commands, `#` issues/PRs/discussions/projects, `!` projects, `@` users/orgs/repos, `/` files | One input box serves many search domains; typing a sigil switches domain instantly instead of needing a separate search field per object type. | The shell's `⌘K`: `@` for vendors, `#` for orders/POs, `/` for inventory items — one box replaces four separate search affordances across pages. | Sigils must be taught (empty-state hint row) or they're invisible; also risks colliding with natural-language search if users type `@restaurant.com` expecting literal text. |
| 14 | **`t`-style single-key fuzzy file/record finder** | object, from any screen | GitHub — [Finding files on GitHub](https://help.github.com/en/github/searching-for-information-on-github/finding-files-on-github) and corroborated via search: press `t` in a repo, type to fuzzy-filter, arrows to move, `Enter` to open, `Esc` to exit | A single un-modified key opens a lightweight fuzzy-filter list scoped to the current context (this repo's files), distinct from the global `⌘K` palette which is unscoped. | `/inventory`, `/cellar`: a bare key (e.g. `f`) opens a fuzzy filter scoped to *this list's* rows, faster than invoking the full global palette. | Needs a clear rule for when a bare letter is safe (not while a text field has focus) — same class of bug GitHub itself has had to guard against. |
| 15 | **Hovercards for any referenced record** | in-place preview, no navigation | GitHub — [Issue and pull request hovercards changelog, 2018](https://github.blog/changelog/2018-10-08-issue-and-pull-request-hovercards/): hovering a link to an issue/PR anywhere on GitHub shows a popup with its key details without opening a new tab | Hovering (not clicking) any reference renders a small preview card; moving away dismisses it; no state change occurs from the hover itself. | `/orders`, `/providers`: hovering a vendor name inside an order preview shows their standing/last delivery without navigating away. | GitHub's real hovercards run noticeably wider than a 320px POPOVER to fit avatar+stats+description — reusing POPOVER as-is may force uncomfortably wordy truncation; may need a documented POPOVER width exception for hover-only, non-interactive cards. |
| 16 | **Hover-to-peek a page's content before opening it** | in-place preview, no navigation | Notion — [official announcement](https://x.com/NotionHQ/status/1716494726445334691): "hover to preview page content, to make sure it's what you're actually looking for," plus [link mentions](https://www.notion.com/help/link-previews) showing a reload/expand-to-block/copy-URL mini-menu on the preview itself | Hovering a page link (not just an external URL) renders a live content preview inline; the preview itself carries its own tiny action menu (reload, promote to full block, copy link). | `/cellar`, `/inventory`: hovering a wine or lot reference previews its current state (last count, price, source) with a "open full record" affordance inside the hover card itself. | The preview's own mini-menu is itself a nested overlay-on-a-hover — needs a rule for what that inner menu is allowed to be (likely nothing beyond "open" / "copy link," never a form). |
| 17 | **Multi-select + bottom/top bulk action bar** | choice, batch | Linear — [Select issues docs](https://linear.app/docs/select-issues): `x` on a highlighted row adds it to selection, `Shift`+click for ranges, `Cmd/Ctrl+A` selects all filtered rows, then "common bulk actions" surface at the bottom of the screen; GitHub Issues corroborates the pattern with a checkbox column + "Bulk actions" dropdown above the list | Selection state persists across scrolling; the action bar appears only while ≥1 row is selected and disappears the instant selection clears — it is not a separate overlay shape, it's a state of the list itself. | `/inventory`, `/team`: selecting multiple lots or shifts surfaces a bottom bar with "plain button" bulk actions (reassign, archive, mark counted). | Matches the house rule directly ("bulk gets a plain button") — low risk, mainly an implementation pattern to adopt as-is. |
| 18 | **Bulk checkbox selection with a dedicated actions dropdown** | choice, batch | GitHub Issues — corroborated via [community discussion on multi-select](https://github.com/orgs/community/discussions/6528) and [bulk-assign guidance](https://www.codestudy.net/blog/how-do-i-assign-multiple-issues-to-a-project-in-github/): checkboxes appear in the leftmost column; a "Bulk actions" control appears above the list once ≥1 row is checked | Row-level checkboxes are always present (not hover-revealed on GitHub, unlike Linear's hover-reveal) — a deliberate trade-off between list cleanliness and discoverability. | `/providers`: a persistent slim checkbox column for vendor rows makes bulk relabeling / bulk archiving discoverable without first learning a keybind. | Choice between "hover-reveal checkbox" (Linear, cleaner) and "always-visible checkbox" (GitHub, more discoverable) is itself an open design fork Mudavym should decide explicitly, not default. |
| 19 | **Split button with a chevron for template/variant choice** | choice, attached to a primary action | Linear's issue-creation flow — corroborated via [Linear issue templates](https://www.temperstack.com/learn/linear/create-issue-templates/) (`⌥C` creates from template; the create surface exposes a "Template" chooser alongside the default create action) | A primary action (Create) ships beside a secondary chevron that opens a short list of variants (templates) — one click for the default path, one extra click for anything else. | `/orders`: "New order" as the primary action, chevron for "from last vendor order" / "from template." | Fits POPOVER (a control's own menu) cleanly — low risk; just needs the chevron's list capped to genuinely a menu, not a form. |
| 20 | **Resizable, keyboard-navigable file tree beside a diff (peek-and-pin)** | in-place, pinned/expandable panel beside content | GitHub — [Improved PR "Files changed" experience, 2025](https://github.blog/changelog/2025-06-26-improved-pull-request-files-changed-experience-now-in-public-preview/): the file tree is resizable, keyboard-navigable with screen-reader landmarks, and shows inline comment/error indicators per file, alongside a searchable "discover comments" side panel | The tree persists beside the content pane (not modal), is user-resizable, and encodes state (has-comments, has-errors) directly in the row rather than requiring a click to find out. | `/reports`, `/documents-reports`: a resizable tree of report sections/attachments beside the open report, each row flagged for "has anomaly" without opening it. | This is a *layout* pattern, not one of the three overlay shapes — safe as long as it's built as a page-level split view rather than smuggled in as a fourth overlay shape. |
| 21 | **Permalink-on-demand ("freeze this exact state into a URL")** | anywhere, addressable | GitHub — [Getting permanent links to files](https://docs.github.com/en/repositories/working-with-files/using-files/getting-permanent-links-to-files) and [`y` shortcut writeup](https://saraford.net/2017/02/21/how-to-press-y-to-navigate-to-the-permalink-for-a-files-exact-commit-id-on-github-com-052/): pressing `y` rewrites the current branch-relative URL into one pinned to the exact commit SHA (and preserves any selected line range) | A single key converts a "moving" URL into a permanently accurate one, so a link shared later still points at what was actually seen. | `/inventory`, `/cellar`: a `y`-style action freezes a lot's current ledger view into a URL that will always show that exact state, even after later corrections. | Requires the underlying data model to support point-in-time reads (an event-sourced ledger, which Mudavym's ledger-rows-expand-in-place design already implies) — mostly a backend cost, not a UI one. |
| 22 | **Every environment/state gets its own shareable, addressable URL by default** | anywhere, addressable | Vercel — [Sharing a Preview Deployment](https://vercel.com/docs/deployments/sharing-deployments) and [Accessing Deployments through Generated URLs](https://vercel.com/docs/deployments/generated-urls): every push to any branch gets a unique public URL automatically, posted as a PR comment, with separate "branch" (always-latest) and "commit" (frozen) link flavors | No explicit "publish" step is needed to get a link — the link exists the moment the state exists; branch-links and commit-links are two distinct, both-first-class URL types for "latest" vs "this exact moment." | The shell: every saved report, every open SHEET, every filtered `/orders` view gets a URL the instant it exists, with an explicit "pin this exact state" action mirroring commit-links. | Direct win for "more access" but raises the same "a draft never looks sent" risk as row 12 if an unfinished/AI-proposed state is trivially linkable and gets forwarded before a person applies it. |
| 23 | **Command palette scoped to the current dashboard/deployment context** | choice, context-aware | Vercel — [Command Menu now available in Deployments](https://vercel.com/changelog/command-menu-now-available-in-deployments): `⌘K` opens on any deployment where the Vercel Toolbar is enabled (prod or localhost) and lets you navigate to the parent Project or sibling Deployments directly from wherever you are | The same palette shortcut resolves differently depending on what object you're currently looking at — it is context-aware, not a single flat global index. | `/orders`, `/providers`: `⌘K` opened from inside a specific PO offers "jump to this vendor" / "jump to this vendor's other orders" ranked above generic global results. | Needs explicit context-ranking rules or the palette becomes inconsistent page to page — a real design decision, not just an engineering one. |
| 24 | **Context-sensitive control surface tied to selection, not to a fixed panel** | in-place, choice | Figma — [Explore component properties](https://help.figma.com/hc/en-us/articles/5579474826519-Explore-component-properties) and [Design, prototype, and explore layer properties](https://help.figma.com/hc/en-us/articles/360039832014-Design-prototype-and-explore-layer-properties-in-the-right-sidebar): the right-side panel's *entire content* swaps based on what's selected — text shows type controls, a shape shows fill/stroke, nothing selected shows page-level controls | The panel is one fixed dock location whose contents are a pure function of selection state — never a separate popup per object type. | `/inventory`, `/team`: a persistent side panel whose fields change entirely based on which lot/shift row is currently focused, instead of opening a new SHEET per row. | This is close to a "sidebar SHEET" already implied by ADR 0112's SHEET shape — mainly a reminder to keep the panel's *content*, not its *container*, doing the contextual work. |
| 25 | **Command menu (`⌘/` or `⌘K`) surfacing recent + all actions in one ranked list** | choice | Figma — [Use the actions menu in Figma Design](https://help.figma.com/hc/en-us/articles/23570416033943-Use-the-actions-menu-in-Figma-Design): `⌘/` (or `⌘K`) opens a single palette combining recent actions, plugins, and every menu command, ranked by keyword match (e.g. "align" surfaces all alignment actions together) | Recency and full command breadth share one list rather than living in separate "recent" vs "all commands" tabs. | The shell: `⌘K` on any Mudavym page leads with the 3–5 actions most recently used *on that page type*, then the full command list below. | Recency-ranking needs per-user, per-page-type state — a real but bounded engineering cost; no conflict with house shapes. |
| 26 | **Reduced-motion contract on every transition** | anywhere (a cross-cutting rule, not one overlay) | Web platform standard — [MDN: prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion): a CSS media feature that detects a user's OS-level request to minimize non-essential motion; a well-behaved interface disables or replaces vestibular-trigger animation (scale/pan) with a simpler or instant alternative when it's set, never just ignores it | Every overlay's open/close/step transition must have a `reduce`-mode fallback that lands in the same end state with zero or near-zero animation, not merely a shorter version of the same motion. | The shell: SHEET slide-in, PANEL fade, POPOVER pop, and peek-style step-through (row 1/2) all need a `prefers-reduced-motion` branch before any of them ship. | No conflict with house rules — this is a pre-condition for shipping *any* of the other 25 patterns accessibly, not a competing pattern. |

## 2. "More access": concrete anywhere-reachability mechanisms

1. **Scope sigils inside one search box.** GitHub's `⌘K` uses `>`, `#`, `!`, `@`, `/` to route one input box across five different object domains instead of five separate search fields. — [GitHub Command Palette beta](https://github.blog/changelog/2021-10-27-command-palette-beta/)
2. **Two-key navigation chords from anywhere in the app.** Linear's `g` + letter jumps straight to any named view (`g i` → Inbox, `g p` → Projects) without ever opening a menu. — [fastshortcuts.com/shortcuts/linear](https://fastshortcuts.com/shortcuts/linear/)
3. **A living, searchable shortcut sheet, one keypress away.** `?` opens Linear's full shortcut reference, itself searchable, so "what can I do here" never requires leaving the keyboard. — [Linear changelog, 2021-03-25](https://linear.app/changelog/2021-03-25-keyboard-shortcuts-help)
4. **A capture surface that lives above the OS, not inside a tab.** Raycast's Floating Notes is summoned by a global hotkey and stays pinned above every other window regardless of what app has focus. — [Raycast announcement](https://x.com/raycastapp/status/1599070998321471489)
5. **Every command has a portable, copyable URL.** Raycast deeplinks (`raycast://...`) let any command — including an AI command — be invoked from outside the app entirely, by a script, a keyboard tool, or a shared link. — [Raycast Deeplinks](https://developers.raycast.com/information/lifecycle/deeplinks)
6. **State exists as a URL from the moment it's created, no publish step.** Every Vercel branch push is a public, addressable URL automatically, posted straight into the PR conversation. — [Vercel: Sharing a Preview Deployment](https://vercel.com/docs/deployments/sharing-deployments)
7. **A single key freezes a moving view into a permanent one.** GitHub's `y` shortcut swaps a branch-relative URL for a commit-pinned one, preserving any selected line range, so a shared link stays accurate forever. — [GitHub permalinks](https://docs.github.com/en/repositories/working-with-files/using-files/getting-permanent-links-to-files)
8. **Hovering substitutes for navigating.** Notion's page-link hover preview and GitHub's issue/PR hovercards both let a reader confirm "is this the right thing" without ever leaving the current page. — [Notion](https://x.com/NotionHQ/status/1716494726445334691), [GitHub](https://github.blog/changelog/2018-10-08-issue-and-pull-request-hovercards/)
9. **The command palette is context-aware, not one flat index.** Vercel's `⌘K` resolves differently depending on which deployment/project you're already looking at, surfacing "jump to sibling" options that only make sense from there. — [Vercel changelog](https://vercel.com/changelog/command-menu-now-available-in-deployments)
10. **Notifications carry the reversing action inline, not a link to go find it.** Gmail's Undo Send and Linear's undo toast both put the "take it back" control directly in the confirmation surface itself, at the moment of the action. — [Gmail](https://blog.google/products/gmail/how-to-unsend-email-gmail/), [Linear](https://linear.app/changelog/undo-actions)

## 3. What a unicorn does that a legacy SaaS does not

1. Fires the action immediately and offers **undo**, instead of blocking on a confirm dialog before anything happens — **Linear** ([undo actions](https://linear.app/changelog/undo-actions)).
2. Lets you **type an argument straight into the command** that invokes it, instead of opening a separate settings/detail screen to set that same value — **Raycast** ([arguments](https://developers.raycast.com/information/lifecycle/arguments)).
3. Lets you **preview a record by hovering or holding a key**, never actually navigating away from the list you're scanning — **Linear peek** ([docs](https://linear.app/docs/peek)), **Notion** ([hover preview](https://x.com/NotionHQ/status/1716494726445334691)).
4. Makes **every state a shareable URL the instant it exists**, with no separate "publish" or "share" step required first — **Vercel** ([preview deployments](https://vercel.com/docs/deployments/sharing-deployments)).
5. Ships a **capture surface that works from anywhere on the machine**, not just from inside the product's own window — **Raycast Notes** ([announcement](https://x.com/raycastapp/status/1599070998321471489)).
6. Treats **keyboard chords as the primary navigation grammar** — single letters and two-key sequences — rather than a power-user layer bolted onto a mouse-first design — **Linear** ([shortcuts](https://fastshortcuts.com/shortcuts/linear/)).
7. **Resolves natural-language time input inline** and shows the parsed result back before commit, instead of forcing a date-picker widget — **Superhuman Command** ([announcement](https://new.superhuman.com/superhuman-command-29123)).
8. Ships **one command box with typed scope sigils** that replaces what would otherwise be four or five separate search fields across the product — **GitHub** ([Command Palette beta](https://github.blog/changelog/2021-10-27-command-palette-beta/)).

## 4. Top 8 for Mudavym (ranked)

1. **Peek-beside-list for line-item records** (`/orders`, `/inventory`, `/cellar`) — the single highest-leverage pattern here: it already rhymes with ADR 0112's "ledger rows expand in place" and needs only to be extended into a keyboard-steppable, non-modal preview rather than a full SHEET open, for the 80% of glance-then-move-on lookups.
2. **Command palette with nested, argument-taking commands** (the shell) — replaces a long tail of small POPOVERs with one consistent `⌘K` surface that drills into pickers, matching both Linear's and Raycast's evidence that this is the highest-throughput single investment for a keyboard-first product.
3. **Multi-select + plain-button bulk action bar** (`/inventory`, `/team`, `/providers`) — directly matches the existing house rule ("bulk gets a plain button") with essentially zero new policy needed, just the UI mechanic itself.
4. **Scoped undo toast for reversible edits** (`/inventory`, `/orders`, `/notifications`) — cuts PANEL-confirmation overhead for anything that's genuinely undoable server-side, while explicitly *not* touching anything that needs wax.
5. **Hover/press-to-preview referenced records** (`/orders` → vendor, `/cellar` → lot) — cheapest pattern to ship (no navigation, no new route), directly serves "show the working" without opening anything.
6. **Deep-linkable overlay state via URL** (the shell, `/reports`) — turns "let me screen-share this" into "here's the link," at the cost of real routing work, but is the multiplier underneath rows 1–5 ever being shareable at all.
7. **Global quick-capture reachable outside the current page** (the shell) — the best-evidenced "more access" mechanic (Raycast Notes), ported to whatever a web SPA can actually offer (a persistent hotkey while the tab has focus, honestly scoped rather than oversold as OS-wide).
8. **Natural-language input inline inside a field** (`/communications`, `/calendar`) — highest polish-per-keystroke payoff but the riskiest to get wrong (timezone/ambiguity bugs), so it's ranked last despite being the most "unicorn-feeling" of the eight.
