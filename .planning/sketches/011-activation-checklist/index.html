A — Top Collapsible Banner
A wide card pinned to the top of the dashboard with a wine-red left border. The user can collapse it to a thin bar or dismiss for the session. Tasks are shown inline — one row each.
Strengths
  • High visibility — immediately seen on login
  • All tasks visible at a glance
  • Collapses cleanly when user wants to work
  • No extra UI chrome required
Trade-offs
  • Pushes dashboard content down
  • Can feel "in the way" for daily users
  • No persistent presence after collapse

B — Sidebar Nav + Slide-in Panel
A persistent badge on a sidebar nav item (like Linear/Notion's setup). Clicking "Getting Started" slides a drawer in from the right with the checklist. Dashboard remains fully visible and uncluttered.
Strengths
  • Dashboard real-estate is 100% preserved
  • Badge is subtle but persistent reminder
  • Feels native to sidebar-nav app patterns
  • Panel can expand with rich content per task
Trade-offs
  • Low initial discoverability
  • Requires intentional click to view progress
  • Needs left sidebar (app must have nav rail)

C — Floating Card (Notion / Intercom style)
A persistent floating card anchored to the bottom-right. Wine-red header, expandable/collapsible. Always present until all tasks are done — then animates away. Zero impact on page layout.
Strengths
  • No layout disruption whatsoever
  • Familiar pattern (Notion, Intercom, Figma)
  • Always accessible without navigating away
  • Collapses to a small pill — stays out of the way
Trade-offs
  • May overlap page content on small screens
  • Could conflict with chat/support widgets
  • Lower discoverability than a banner

D — Dashboard Widget Card
The checklist lives as a first-class widget in the dashboard grid alongside inventory and order cards. It has a progress ring showing X/3 complete. Feels native — part of the dashboard, not an overlay.
Strengths
  • Feels native — part of the dashboard data
  • Progress ring is a compelling visual
  • Disappears naturally when done (widget slot freed)
  • No separate UI layer to manage
Trade-offs
  • Takes up a widget slot permanently until done
  • Users may want to rearrange grid (not standard)
  • Less contextual than a banner or panel
