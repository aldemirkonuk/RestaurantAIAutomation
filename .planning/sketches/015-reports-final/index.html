Section placement rationale
Minimal code change — sections slot into existing <canvas> flex column. No new route or page needed.
①
KPI CardsTop — pinned
Already first. Draggable individually within the 4-column grid. Summary numbers that tell you if today was good or bad.
②
Revenue trend + HeatmapRow 1
8/4 split. Trend answers "how did this week go?", heatmap answers "when are we busiest?". Together they set the operational context.
③
Channel donut + Labor overlayRow 2
4/8 split. Donut is compact and answers "where did revenue come from?", labor overlay answers "did we staff efficiently?". Managers read these together.
④
Order funnel + Wine consumption analyticsRow 3
4/8 split. Funnel = guest behavior. Consumption analytics = wine velocity by type. Both need context from rows 1–2 first. Wine consumption analytics is the existing WineDistributionChart surfaced as a proper card.
⑤
Daily breakdownCollapsible · open by default
Already exists as DailyBreakdownTable. Moved up (before purchased wines) so the raw day-by-day numbers are right below the visual trend. Add "vs. prev" column — tiny delta.
⑥
Purchased winesCollapsible · collapsed
Already exists as PurchasedWinesTable. No change needed — just reorder below Daily Breakdown. Add Margin column if not already shown.
⑦
Monthly stock reconciliationCollapsible · collapsed · NEW
New section. Computes expected stock = opening + purchases − sales, compares against physical count. Badge shows variance count. Collapsed by default — managers open it monthly.
⑧
Digital check scannerCollapsible · collapsed
Already exists as CheckScannerSection. Keep as-is but move below Reconciliation. "Upload check" button stays in the section header so it's always accessible even when collapsed.
⑨
Report generatorCollapsible · collapsed · last
Already exists as <ReportGenerator>. Move to the very bottom — it's an action tool, not a data view. Managers scroll here intentionally to generate a report, not accidentally.
Drag-and-drop implementation note
Rows ②–④ and sections ⑤–⑨ all use the HTML5 Drag API (draggable="true", dragstart/dragover/drop). Each block gets an ID stored in the existing dashboardBlocks state array — reordering just updates the array, which is already persisted to user preferences via serializeDashboardBlocks. Zero new state, zero new storage. The 6-dot grip icon appears on hover at top-left of each draggable block.
