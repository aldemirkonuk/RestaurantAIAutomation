The idea

B's grid. C's clock as the tab order, the holder on the tab. A's record inside the line sheet.

This is the desk the README recommends, drawn so the founder approves a screen and not a sentence. The page is still one delivery at a time, four numbers per line, a verdict derived from entries, an answer owed. Two grafts: the deliveries across the top are C's queue in clock order — the soonest window first, with the holder on the tab (D9: no unowned backlog) — so the manager never guesses which delivery to open; and pressing a row opens the line sheet, one object at 440 px, which carries A's record for that line (order, paper, count, comparison, nudge, entries, all on one rail by name) above the ledger, the held append, and the answer. Section 3 draws the grid at about 1100 px with the column-hiding rule applied.

2b · The rule's other two cases

The derived box with no order, and with more than was ordered

"Current portions add up to the ordered quantity" is undefined for an unordered line and for an over-delivery. The rule (README, "The derivation rule"): with no order the basis is the counted quantity, or the on-paper quantity if nobody counted; a portion beyond the order is marked as such, and the invariant compares to max(ordered, counted).
