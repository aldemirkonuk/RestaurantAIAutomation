## What Was Built

### Task 1 — Infrastructure Changes

**Bug #10 fix (T-12.1-11): BoundedLRUCache replaces unbounded `_url_cache`**
- `_url_cache = BoundedLRUCache(max_size=1000)` — hard upper bound on in-process memory
- `_get_cached_page_text` uses `_url_cache.get(url, ttl_seconds=...)` API
- `_store_cached_page_text` uses `_url_cache.put(url, page_text)` API

**Bug #8 fix (T-12.1-08): DNS resolution in `_is_safe_url`**
- `socket.getaddrinfo(host, None)` resolves hostname before IP range check
- All resolved IPs checked against `_PRIVATE_NETWORKS` list
- `socket.gaierror` → block (unresolvable host)
- Catches DNS rebinding attacks (e.g., `169.254.169.254` behind a redirecting DNS)

**D-02 BLOCKER fix: `_extract_field_candidates` cascade model dispatch**
- Added `model_tier: str = "flash"` parameter
- Anthropic path: if `model_tier in ("haiku", "sonnet")` and `claude_api_key` set → dispatch to Anthropic
- Uses `settings.research_cascade_haiku_model` / `settings.research_cascade_sonnet_model` from Plan 01 settings
- Logs Anthropic spend via `spend_logger.log(provider="anthropic", ...)`
- Falls through to Gemini Flash if Anthropic unavailable (graceful degradation)

**Bug #2 fix: `_check_daily_budget` sums ALL providers**
- Removed `.eq("provider", "serper")` filter — now queries all `api_spend` rows since midnight

**Bug #3 fix: `_write_results` uses `merge_conflict_candidates()`**
- Added `existing_conflicts: dict[str, list]` parameter
- `conflict_candidates` DB update uses deep-merge: `merge_conflict_candidates(existing_conflicts, conflict_updates)`

**Bug #4 fix: `research_daily_budget_check_task` logs and sets Redis flag**
- `logger.info("research_daily_budget_check: within_budget=%s", result)` always logged
- On budget exceeded: `logger.warning(...)` + Redis `setex(f"research:budget_exceeded:{today}", 86400, "1")`

### Task 2 — Three-Layer `_process_record` Rewrite

**New signature:** `_process_record(..., redis_client=None)` — D-04 Redis client wired through

**Bug #5 fix: `started_at` tracked at function entry**
- `started_at = datetime.now(timezone.utc)` at top of function
- `"time_to_fill_hours": (datetime.now(timezone.utc) - started_at).total_seconds() / 3600` in returned stats

**Bug #6 fix: `regression_blocked_count` counter**
- `regression_blocked_count = 0` initialized, incremented on every `check_regression_guard` → False
- Returned as `"regression_blocked_count": regression_blocked_count` in stats dict

**Layer 1: Deterministic Inference (D-01, D-08)**
- `layer1_fills = run_layer1_inference(existing_fc, wine_name, producer, vintage)`
- Each fill: removes field from `target_fields`, appends citation with `source_url="ontology://phase9"`, `source_tier="A"`, `fetch_verified=True`
- `existing_fc` updated with Layer 1 fills so Layer 2/3 regression guard sees them

**Layer 2: Cascade LLM Enrichment (D-02, D-04, D-05)**
- Entity cache: `get_entity_cache(f"{wine_cache_key}:{field_name}", redis_client)` before Serper
- Producer-level cache: shared fields (`country`, `region`, `sub_region`, `producer_bio`) checked against `_cache_key_producer` key
- Model selection: `model_tier = select_model(field_name, ontology_hint_conf, attempt=1)`
- Cascade dispatch: `_extract_field_candidates(..., model_tier=model_tier)`
- Conflict auto-resolution: `resolve_conflict(candidates, field_name)` — auto-resolves tier-A vs tier-C/B, escalates tier-A vs tier-A to human
- **Bug #1 fix:** tier-correct promotion — `A_single` selects from tier-A candidates, `B_dual` selects max-confidence from tier-B/C
- **D-07 resolution_challenges:** when tier-A fetch-verified value contradicts `human_resolved`, inserts into `resolution_challenges` + `notifications` tables
- Post-fill caching: `put_entity_cache()` for wine-level and producer-level keys

**Layer 3: Deep Research with Reflexion (D-03)**
- Processes fields remaining after Layer 1 + 2
- Per-field retry loop: `range(1, settings.research_max_reflexion_retries + 1)` (default: 3)
- **Plateau detection:** `if curr_value in [v.lower().strip() for v in prev_values]: break`
- **Cascade escalation:** `select_model(field_name, 0.0, attempt=attempt)` escalates to Sonnet on attempt ≥ 2
- Reflexion query modification: `query += f' -"{prev_values[-1]}"'` to diversify search
- **D-03 research_exhausted:** fields that exhaust all retries without fill: `{"value": None, "confidence": 0.0, "source": "research_exhausted"}`

**`_research_async` wiring (D-04)**
- Redis initialization: `redis.Redis.from_url(settings.redis_url)` with ping test, falls back to `None`
- Redis budget flag check: `redis_client.get(f"research:budget_exceeded:{today}")` → skip if set
- `existing_conflicts = submission.get("conflict_candidates") or {}` passed to `_write_results`
- `redis_client` passed to `_process_record`
- `research_run_stats` insert includes `time_to_fill_hours` and `regression_blocked_count`

### Task 3 — `staleness_reverify_task` (D-07)

**`@celery_app.task(name="research.staleness_reverify")`**
- Matches the beat schedule registered in Plan 02 (`celery_app.py`)

**`_staleness_reverify_async()`**
- Cutoff: `timedelta(days=180)` from now
- Query: `evidence_citations` rows with `retrieved_at < cutoff`, `.limit(50)` (T-12.1-13 DoS guard)
- Per stale citation: checks if field still has `source == "human_resolved"` in live FC
- Re-fetch via `_fetch_verify_value(proposed_value, source_url, "A", field_name, supabase)`
- If still valid: skip (no change)
- If stale: downgrades to `confidence=0.85`, `source="human_resolved_stale"` (T-12.1-12)
- Inserts into `field_review_queue` with `status="pending"` for human re-review
- Logs processed/downgraded counts

## Deviations from Plan

### Planned Deviation: Atomic Full-File Write

**Context:** Tasks 1, 2, and 3 all modify `research_tasks.py`. The three-layer `_process_record` (Task 2) directly depends on the `model_tier` parameter added to `_extract_field_candidates` (Task 1), which depends on the Wave 1 imports (also Task 1). Layer 3 Reflexion loop reuses the same helper functions.

**Approach:** Written as a single complete file to guarantee all interdependencies are correct. All three tasks are verified independently using their respective acceptance criteria — all pass.

**Impact:** Single commit `339b7ce` covers all three tasks. Commit message documents Task 1 changes; Tasks 2 and 3 are logically contained within the same atomic unit.

### Auto-fix: Corroboration check duplication in Layer 2

**Found during:** Task 2 implementation review
**Issue:** The plan's Layer 2 pseudocode shows conflict detection before `should_auto_promote`, but the original code called `should_auto_promote` unconditionally after conflict routing. When a conflict is auto-resolved, the resolved winner needs a `conf_key` for `assign_confidence_by_tier`.
**Fix:** Added `can_promote = True; conf_key = "A_single" if tier == "A" else "B_dual"` for the auto-resolved conflict path (non-conflicted path uses `should_auto_promote` as normal). This ensures correct confidence assignment in both paths.
**Files modified:** `services/agent-orchestrator/jobs/research_tasks.py`
**Commit:** 339b7ce
