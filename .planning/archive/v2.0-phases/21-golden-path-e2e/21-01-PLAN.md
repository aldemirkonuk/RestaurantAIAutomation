<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| env vars → Settings | Attacker who controls env can inject arbitrary rabbitmq_url, toast credentials |
| settings.py → orchestrator | Settings values flow into aio-pika connection strings and HTTP auth headers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-01-01 | Information Disclosure | settings.py — toast_client_secret, plivo_auth_token printed in logs | mitigate | Ensure no `logger.info(str(settings))` or `print(settings.__dict__)` anywhere in codebase. Optional[str] fields with None default reduce blast radius. |
| T-21-01-02 | Tampering | rabbitmq_url constructed from env components | accept | Localhost default only. Production URL will be set explicitly via RABBITMQ_URL. Low risk in dev. |
| T-21-01-03 | Elevation of Privilege | supabase_service_role_key alias exposes elevated DB key to agent code | mitigate | Key already exists in SUPABASE_SERVICE_ROLE_KEY env var; this alias only avoids AttributeError. No new exposure introduced. |
</threat_model>
