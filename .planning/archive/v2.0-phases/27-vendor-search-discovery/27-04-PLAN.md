# Phase 27 — Plan 04: Frontend — Branch Provider Transfer Modal + Order Guard Popup

## Objective
Complete the vendor feature surface by building the branch provider transfer flow (triggered after
adding a new location) and the order creation guard that blocks orders when no vendors are configured.

## Tasks

### Task 1: BranchProviderTransferModal
`apps/web/src/components/providers/BranchProviderTransferModal.tsx`

Props:
```typescript
interface BranchProviderTransferModalProps {
  open: boolean
  onClose: () => void
  newBranchName: string
  newRestaurantId: string
  currentProviders: Provider[]
}
```

Structure:
```
┌──────────────────────────────────────────────────────────┐
│  Add vendors to [New Branch Name]?              [×]      │
│                                                          │
│  Your current providers are listed below.               │
│  Select which ones to add to this new location.         │
│                                                          │
│  ☑ Southern Glazers Wine & Spirits                      │
│  ☑ Winebow Group                                        │
│  ☑ Skurnik Wines                                        │
│  ☐ (user unchecked this one)                            │
│                                                          │
│  [Transfer 3 Selected]          [Skip for now]          │
└──────────────────────────────────────────────────────────┘
```

Behavior:
- All checkboxes start checked (user unchecks to exclude)
- "Transfer X Selected" button shows the count dynamically
- On transfer: calls `POST /api/v1/providers` for each checked provider with the new `restaurant_id`
- Shows loading state per-transfer with a progress indicator
- On completion: success toast "3 vendors added to [Branch Name]"
- "Skip for now" immediately closes without any API calls

### Task 2: Wire BranchProviderTransferModal into AddLocationDialog
In `apps/web/src/components/locations/AddLocationDialog.tsx`:
1. Add state: `transferModal: { open: boolean, newBranchName: string, newRestaurantId: string }`
2. In the `onSuccess` handler of the location creation API call:
   - If the restaurant has any existing providers: set `transferModal.open = true`
   - If zero providers: close the dialog normally (no need to show empty transfer modal)
3. Render `<BranchProviderTransferModal>` at the bottom of the dialog tree

### Task 3: OrderGuardModal
`apps/web/src/components/orders/OrderGuardModal.tsx`

Props:
```typescript
interface OrderGuardModalProps {
  open: boolean
  onClose: () => void
}
```

Structure:
```
┌──────────────────────────────────────────────────────┐
│  Add a vendor to place orders                        │
│                                                      │
│  🚫  You don't have any wine vendors set up yet.    │
│                                                      │
│  Before you can place orders, add at least one      │
│  distributor or supplier to your Providers list.    │
│                                                      │
│  [Go to Providers →]       [Back to Order]          │
└──────────────────────────────────────────────────────┘
```

Design: uses wine-red accent for the icon; non-destructive framing (it's a helpful nudge, not an error).
"Go to Providers →" navigates to `/providers` and closes modal.

### Task 4: Wire OrderGuardModal into CreateOrderModal
In `apps/web/src/pages/orders/CreateOrderModal.tsx`:

**Option A — Pre-flight check** (preferred, avoids network round-trip):
```typescript
const { data: providers } = useProvidersQuery() // existing hook
const canOrder = providers && providers.length > 0

// On form submit:
if (!canOrder) {
  setShowOrderGuard(true)
  return
}
```

**Option B — Backend 403 handler** (fallback):
If the orders API returns `{ reason: 'no_vendors' }`, catch it and show `OrderGuardModal`.

Implement both: pre-flight as primary, 403 handler as safety net.

### Task 5: Update services/api/providers.ts
Add `bulkCreateProvidersForBranch(providers: Provider[], newRestaurantId: string): Promise<void>` 
for the branch transfer operation.
