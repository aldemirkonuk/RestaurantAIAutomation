# Phase 27 — Plan 01: Database — vendor_catalogue + providers schema update + seed

## Objective
Create the `vendor_catalogue` table (admin-curated, globally readable), update the `providers` table
to link catalogue entries, and seed the catalogue with 20+ US wine distributors from our existing
`providerData.ts` data.

## Tasks

### Task 1: Create `vendor_catalogue` migration
File: `supabase/migrations/20260509000001_vendor_catalogue.sql`

```sql
-- Phase 27 VENDOR-01: Global admin-curated vendor catalogue
-- This table is NOT restaurant-scoped. It is maintained by WineOps admins.
-- Restaurant users can read all rows; only service_role can write.

CREATE TABLE IF NOT EXISTS vendor_catalogue (
  id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name           TEXT NOT NULL,
  type           TEXT CHECK (type IN ('distributor', 'importer', 'wholesaler', 'winery_direct', 'broker', 'other')),
  country        TEXT NOT NULL DEFAULT 'US',
  state          TEXT,        -- for US regional distributors (e.g. 'CA', 'NY')
  city           TEXT,
  address        TEXT,
  phone          TEXT,
  email          TEXT,
  website        TEXT,
  wine_specialties TEXT,      -- e.g. 'Burgundy, Champagne, Bordeaux'
  notes          TEXT,
  is_active      BOOLEAN NOT NULL DEFAULT TRUE,
  created_at     TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at     TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Index for fast search
CREATE INDEX IF NOT EXISTS idx_vendor_catalogue_name ON vendor_catalogue USING gin(to_tsvector('english', name));
CREATE INDEX IF NOT EXISTS idx_vendor_catalogue_country ON vendor_catalogue (country);
CREATE INDEX IF NOT EXISTS idx_vendor_catalogue_state ON vendor_catalogue (state);

-- RLS
ALTER TABLE vendor_catalogue ENABLE ROW LEVEL SECURITY;

-- Any authenticated user can read
CREATE POLICY "vendor_catalogue_read" ON vendor_catalogue
  FOR SELECT TO authenticated USING (is_active = TRUE);

-- Only service_role can write (admin operations)
-- INSERT/UPDATE/DELETE not exposed to anon/authenticated roles
```

### Task 2: Update `providers` table
File: `supabase/migrations/20260509000002_providers_catalogue_link.sql`

```sql
-- Phase 27 VENDOR-02: Link providers to vendor_catalogue + is_custom flag

ALTER TABLE providers
  ADD COLUMN IF NOT EXISTS catalogue_vendor_id UUID REFERENCES vendor_catalogue(id) ON DELETE SET NULL,
  ADD COLUMN IF NOT EXISTS is_custom BOOLEAN NOT NULL DEFAULT TRUE;

-- Index for catalogue lookups
CREATE INDEX IF NOT EXISTS idx_providers_catalogue_vendor ON providers (catalogue_vendor_id)
  WHERE catalogue_vendor_id IS NOT NULL;

-- Update existing providers: if they pre-exist they are all custom
UPDATE providers SET is_custom = TRUE WHERE catalogue_vendor_id IS NULL;
```

### Task 3: Seed vendor_catalogue
File: `supabase/seed/vendor_catalogue_seed.sql`

Translate all entries from `apps/web/src/data/providerData.ts` into INSERT statements.
Each entry maps: name, type='distributor', country, state, phone, email, website, wine_specialties from winePortfolio field.

Use `ON CONFLICT (id) DO NOTHING` to make seed idempotent.

Example:
```sql
INSERT INTO vendor_catalogue (id, name, type, country, state, city, phone, email, website, wine_specialties) VALUES
  (gen_random_uuid(), 'Southern Glazers Wine & Spirits', 'distributor', 'US', NULL, 'Miami', '+1-305-625-4171', 'info@southernglazers.com', 'https://www.southernglazers.com', 'Bordeaux, Burgundy, Champagne, Napa Valley, Tuscany, Rioja, Barossa Valley'),
  -- ... all other entries from providerData.ts ...
ON CONFLICT DO NOTHING;
```
