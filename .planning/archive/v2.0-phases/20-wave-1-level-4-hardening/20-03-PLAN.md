<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internal message bus → NotificationAgent | Incoming alert messages; event_id is trusted from internal bus |
| NotificationAgent → SMS/Email providers | Outbound calls to Plivo / Gmail / SendGrid — credentials in config |
| NotificationAgent → Supabase | notification_deliveries writes; status enum constrained by CHECK constraint in DDL |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-03-01 | Spoofing | event_id used as idempotency key | accept | event_id comes from internal RabbitMQ bus (not external input); bus is not externally accessible |
| T-20-03-02 | Tampering | notification_deliveries status field | mitigate | CHECK constraint on status column enforces only 'sent', 'failed', 'pending' — invalid values rejected at DB level |
| T-20-03-03 | Repudiation | Failed notifications | mitigate | Every failure persisted to notification_deliveries with error text + DLQ after 3 failures — full audit trail |
| T-20-03-04 | Information Disclosure | Error messages written to notification_deliveries.error column | accept | Internal table, not externally queryable; contains delivery error details that are not sensitive PII |
| T-20-03-05 | Denial of Service | Retry loop with DLQ escalation | mitigate | DLQ triggered after exactly 3 failures — prevents infinite retry loops from exhausting channel provider rate limits |
</threat_model>
