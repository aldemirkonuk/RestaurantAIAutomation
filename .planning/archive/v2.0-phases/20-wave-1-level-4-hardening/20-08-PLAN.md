# Plan 20-08: Payload Shape Guard Rails (POS saga trigger + InventoryEngine dedup key)

## Objective

Fix two "silent failure" scenarios where the agent receives a valid-looking message but the
idempotency or saga logic silently skips processing due to unexpected payload shape.

### Gap D — POSIntegrationAgent saga trigger (confidence 0.65)

The polling fallback saga only triggers when `data.order.selections` (nested Toast shape) is
empty. A caller sending `{"items": [], "order_guid": "x"}` at the top level bypasses the trigger
entirely — POS data is silently dropped with no saga, no log, no error.

### Gap E — InventoryEngine dedup key (confidence 0.7)

Idempotency key is the envelope `message_id`. If the message bus delivers a message without a
stable top-level `message_id` (e.g., generates a new UUID per delivery), dedup is bypassed and
stock state can be double-written.

## Fixes

### D: POSIntegrationAgent — normalize item extraction in `handle_order_completed`

Add a fallback that checks top-level `items` if `data.order.selections` is empty/absent:

```python
# Existing: selections from nested Toast shape
order = webhook_data.get("data", {}).get("order", {})
checks = order.get("checks", [{}])
selections = checks[0].get("selections", []) if checks else []

# Add fallback to top-level items
if not selections:
    selections = webhook_data.get("items", [])

if not selections:
    # Still empty after both paths — trigger saga
    enriched_items = await self._handle_incomplete_webhook(order_guid, webhook_data)
```

Log which path resolved items (for observability):
```python
self.logger.debug(f"Item source: {'nested selections' if nested_found else 'top-level items' if toplevel_found else 'saga fallback'}")
```

### E: InventoryEngine — dedup key fallback chain

In `_handle_stock_evaluated`, `_handle_manual_correction`, `_handle_delivery_received`:

```python
# Before:
message_id = message.get("message_id", "")

# After:
message_id = (
    message.get("message_id")
    or message.get("payload", {}).get("event_id")
    or message.get("event_id")
    or ""
)
if not message_id:
    self.logger.warning("No stable message_id or event_id in message — idempotency bypassed")
```

This makes dedup robust to buses that omit `message_id` while the caller sets `payload.event_id`.
