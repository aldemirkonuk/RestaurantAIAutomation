# Plan 20-06: InventoryEngine Event Sequence Monotonicity

## Objective

Replace the hard-coded `sequence_number=1` in every `append_event` call inside InventoryEngine
with a per-aggregate monotonic counter. Without this, event replay is impossible: all events for
an inventory item have sequence_number=1, so ordering and deduplication by sequence are broken.

**Risk without fix:** Phase 21 E2E and any future event-sourced read model will reconstruct
inventory state incorrectly if it relies on sequence ordering.

## Root Cause

All three `append_event` calls in `inventory_engine.py` pass `sequence_number=1` (hardcoded):
- `_handle_stock_evaluated` → `StockUpdated`
- `_handle_manual_correction` → `ManualCorrectionApplied`
- `_handle_delivery_received` → `DeliveryReceived`

## Fix

### 1. Add in-memory sequence counter to `__init__`

```python
self._event_sequence: dict[str, int] = {}  # aggregate_id → last sequence_number
```

### 2. Add helper method `_next_sequence`

```python
def _next_sequence(self, aggregate_id: str) -> int:
    self._event_sequence[aggregate_id] = self._event_sequence.get(aggregate_id, 0) + 1
    return self._event_sequence[aggregate_id]
```

### 3. Replace all `sequence_number=1` calls

```python
# Before:
await self.append_event("inventory", str(inventory_id), "StockUpdated",
    payload={...}, sequence_number=1)

# After:
await self.append_event("inventory", str(inventory_id), "StockUpdated",
    payload={...}, sequence_number=self._next_sequence(str(inventory_id)))
```

Apply to all three handlers: `_handle_stock_evaluated`, `_handle_manual_correction`,
`_handle_delivery_received`.

**Note:** Counter is in-memory only — resets on agent restart. Acceptable for Phase 20; persistent
sequence tracking (read from event_store max) is deferred to Phase 21 if needed.
