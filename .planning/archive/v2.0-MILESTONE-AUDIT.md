## Cross-Phase Integration Findings

Full detail in the [integration-checker subagent's report](6d1da750-f5d3-4a32-aace-f924f5d9bad6). Headline findings:

1. **BROKEN — Inbound Gmail intelligence pipeline (Phase 24).** `EmailIntelAgent` and `EmailParsingAgent` are fully implemented but never registered in `core/orchestrator.py`'s agent registry, so nothing consumes inbound vendor emails — independent of whether Phase 23's OAuth2 credentials are ever provisioned. There's also a routing-key mismatch (`email.inbound.raw` has zero publishers; the real webhook emits `email.inbound.received`). Outbound provider email is **not** blocked — it has a working SMTP app-password fallback.
2. **PARTIAL — golden path documentation accuracy.** The real event chain is `POSIntegrationAgent → BufferManager → InventoryEngine`, not the ROADMAP's simplified `POSIntegrationAgent → InventoryEngine`. `ReportingAgent` never subscribes to `stock.events` at all, contradicting the Phase 21 success-criteria wording (functionally the E2E flow still completes; only the documented topology is wrong).
3. **PARTIAL — approveDraft is not literally atomic.** Order-status update, shadow-stock reservation, and calendar-event creation are split across `approveOrder()` and `approveDraft()` with no shared transaction. Today's behavior is safe (matches Phase 34's integrity *goal*), but a partial failure between the two calls could leave inconsistent state, and it doesn't match the "atomically" wording in Phase 34's own success criteria.
4. **WORKING — Phase 26→33 membership bugs already fixed.** The specific bugs Phase 33 was scoped to fix (`joinViaInvite` crash, unwritten `user_restaurant_access`) already appear resolved in `auth.service.ts`, along with supporting migration/service/frontend files — despite ROADMAP.md still showing all 5 Phase 33 plans unchecked. This looks like a tracking/roadmap drift rather than a live bug, but should be reconciled (either mark Phase 33 done, or explain what's actually still missing).
5. **WORKING / NOT_APPLICABLE — clean boundaries elsewhere.** Phase 27's zero-provider hard block has no dangling Phase 29 references; Phase 30's calendar has no dangling Phase 31 references; Phase 36/37's synthetic-tenant conventions are precisely aligned; Phases 38–43 have zero premature/orphaned code.
