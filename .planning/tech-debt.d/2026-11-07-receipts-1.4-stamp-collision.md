## The resolution log says `matched` for a paper the stamp set aside as a duplicate — OPEN — 2026-11-07

Filed by `fix/vendor-stamp-collision-is-a-duplicate-verdict` (proposal-receipt §3, Phase 1A row 1.4; founder /goal 2026-11-07 delegated the forks).

**What is true.** `resolveVendor` appends its `document_vendor_resolutions` row (state `matched` or `created`, `provider_id` set) before `applyToDocument` runs. When the stamp then collides with `uq_pd_restaurant_provider_type_number`, the document keeps `provider_id` NULL and gets `intake_verdict = 'duplicate'` with a sentence naming the earlier paper, but the log row still names the provider. `latestFor` therefore answers "matched to prov-X" for a document that holds no vendor. The verdict and its sentence are the truth on the document; the log records the reading, not the outcome.

**What closes it.** Either the log gains a state (or a follow-up row) for "resolved, set aside as a duplicate", or `latestFor`'s readers check the document's verdict. Needs a migration if a state is added (the log's state check).

## The intake door ignores what `applyToDocument` returns — OPEN — 2026-11-07

Filed with the entry above.

**What is true.** `document-intake.service.ts:1233` awaits `applyToDocument` and drops its return value, so the new failure sentences (lookup failed, earlier paper missing on a second read, verdict write refused) reach only the gateway log (`logger.warn` in `vendor-resolution.service.ts`). The method's contract (string on failure) holds; nobody reads it. The caller was left alone on purpose: open PR #688 edits that file.

**What closes it.** After #688 merges, the door carries the string into its `VendorResolution` answer (or its `reason`), so a failed collision record is visible where the paper was taken in.

## A same-number paper is called `duplicate` whether or not its bytes differ — OPEN — 2026-11-07

Filed with the entries above.

**What is true.** Row 1.4 writes `duplicate` for any number collision the stamp hits. Row 1.1 of the same proposal deliberately does not call a different-bytes same-number paper a duplicate at the door, because what it becomes (a revision, a copy, a replacement) is the proposal's Decision 3. The sentence written here says only what is known: the number is already on file from the same vendor, and this paper was not filed under the vendor a second time. It does not claim the two are the same file.

**What closes it.** Decision 3, recorded in an ADR; this verdict is then narrowed to match it.
