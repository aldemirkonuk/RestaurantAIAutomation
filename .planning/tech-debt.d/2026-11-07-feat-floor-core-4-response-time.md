## The response-time port's caller owes these before its figures go to managers — OPEN — 2026-11-07

Found by the ADR 0090 session audit of PR #768 (`packages/floor-core/src/response-time.ts`). `responseSamples` has no caller yet; these fall to the floor gateway that builds `SeatingFacts`, and to the report that ranks waiters (ADR 0346).

1. **Pass null, never `""`.** `caretakerAtSeatId ?? curr.actorId` keeps `""`, so a gap whose credited id is `""` (or null) is dropped from every waiter's figure without a trace; a null or `""` previous actor is replaced, by the handoff rule, with a non-empty current one; a `""` current actor is not, so a real previous actor's gap drops. The uuid columns cannot produce `""`; a caller that builds facts from anything else must normalise. The package keys on `seatingId` alone, so the caller also scopes events and facts to one house.
2. **A table with no caretaker at seat time** (none assigned, cleared as absent under ADR 0351 `:23`, or `caretaker_at_seat_id` set null by `ON DELETE SET NULL` in the floor's record migration) leaves its open greeting gap out of every waiter's figure; past T, it counts for the table only, and only when the table is not hidden. The board and report should show such seatings as uncovered rather than let the silence vanish.
3. **Credit follows the visit.** A colleague's or manager's check-in carries the open gap after it (the handoff rule), bounded by the caretaker's last tap; with a caretaker, anyone's first check-in closes the caretaker's greeting gap, so a colleague's tap can end it early; and with no caretaker, the first visitor, a manager who seated included, takes the greeting gap. The report decides whether manager ids appear in waiter rankings. Who may mark someone absent is an input to these figures too, and D8's split for a caretaker who goes absent before the first visit is not built (ADR 0351 `:29`): until it is, the caller clears an absent caretaker's id itself.
4. **Pass every field the facts promise.** `tableHidden` must be an explicit `false` for a shown table: a missing flag reads as hidden and keeps the table out of the per-table figures (its gaps stay in the waiter's, F7). `caretakerLastTapAt` is the seat-time caretaker's last tap on any table that service day, not on this one, and not the current caretaker's after a reassignment; null leaves the open gap to end at the earliest of Paid, leave and `now`, so a past-day report passes the tap it knows, and null only when there is no caretaker or no tap. An undone Paid (ADR 0353 `:43`) is passed as null.
5. **Show what was not measured.** The report surfaces `seatingsWithoutFacts`, `seatingsWithoutAnchor` and `seatingsNotClosed`, so a seating whose facts or anchor are missing, or that was never closed, is listed. Some drops are in none of those lists, and the caller must catch them itself. Those found so far, not a closed list: a no-caretaker seating's open greeting gap (item 2, shown as uncovered); a gap whose credited actor is null or `""` (item 1); an event whose time is unreadable, or that has no seating id; a gap on a null or `""` table id, which reaches the waiter's figure but no table's; a seating whose Paid or leave is stamped before its seat time, which leaves no anchor in the window; and an unreadable `caretakerLastTapAt`, which reads as no tap and runs the open gap to Paid, leave or `now`, so the caller checks the tap parses before passing it.

These are executor's readings under OD-242 (the header's readings paragraph); ADR 0346 `:64` names only who must not get the greeting gap.
