## Defects seen on production while recording the YC demo — OPEN — 2026-11-02

Filed by `docs/demo-day-defects`. Each was seen live on mudavym.com on 2026-11-02 while recording in two sample houses (Sim Meyhouse `a229f22b-…`, Tuzlu Rüzgar `b9d520a1-…`). None has a fix in this branch. Verify each before acting on it (CLAUDE.md §5b).

1. **The receipts desk never compares.** `CanonicalDocumentService` calls `canonicalFromParsedDocument` without `spine` (`apps/api-gateway/src/procurement/canonical/canonical-document.service.ts:399`), so `layer3` has no ordered or received quantity and `VerdictBlock.tsx:221` always prints "Not compared — no order or door count to compare against", even for a document linked to an order with a confirmed line pairing (document `8008b652-…`, line `ee14e6c1-…` → order line `91c92ebf-…`). A price above the agreed one is never flagged.
2. **A door photo pairs no lines by itself.** `linkAndMatch` links the order but leaves the 0.88 description match as a suggestion; nothing on the door path confirms it, so the desk shows "Names no shelf yet" on every line.
3. **A credit request drafted at the door disappears.** Marking a delivery Short-shipped shows "CREDIT REQUEST — DRAFTED, UNSENT" on the door screen and "The credit request rides with it", but after sealing it appears nowhere: not Receiving's "Drafted, not sent", not Receipts → Credits ("No credit claim has been opened at this house"), not the counter (orders ORD-2026-79272, ORD-2026-10169).
4. **Boxes are recorded as bottles.** Sealing "1 box in" against a 12-bottle order records "1 bottles counted by case" and leaves the order PARTIALLY_RECEIVED (ORD-2026-50023).
5. **A new order for a partly received wine is merged, and the panel says it was placed.** `createOrder`'s dedup treats PARTIALLY_RECEIVED as open (`procurement.service.ts` TERMINAL_STATUSES), so the new line updates the old order, while `NewOrderSheet.tsx:718` prints "Placed as ORD-… It is pending until somebody approves it." The order list also labels PARTIALLY_RECEIVED rows "DELIVERED".
6. **Communications crashes on "Read it".** Opening a drafted order letter from "Waiting on you" (`/communications?reply=…`) renders the error page "Cannot read properties of null (reading 'toLowerCase')" (Tuzlu Rüzgar, Sarnelia order ORD-2026-51212); the boundary persists until another route is visited.
7. **A 429 on `/auth/me` still ends at /login.** `AuthContext` keeps the tokens on a 429 ("Keeping the session…" in the console) but the route guard sends the user to the sign-in page anyway; many full reloads in a minute trigger it.
8. **Ask Mudavym answers nothing.** "Did Larkspur bill us more than we agreed on this week?" and "What did we spend with Larkspur this month?" returned "No answer was written — the answer failed Mudavym's checks"; "What arrives today?" returned 0 records.
9. **"Draft the PO" opens Orders without a draft.** From the Sonoma County Chardonnay stockout entry, `/orders?rec=stockout_imminent&from=recommendations&draft=1` shows the plain order book.
10. **The order letter is generic.** Approving an order stages a letter that reads "Hi! Just wanted to reach out and check in…" rather than the order.
