## The goal producers tell no one about a days-of-stock goal — OPEN — 2026-11-01

OPEN means the missing gate; the claim it names is `resolved` because it pins the skip that stands in for the gate. Filed when PR #617 was split. A days-of-stock goal is a sales holder's figure (ADR 0298 decision 9, `0298-…md:70`), and `ceiling-held.producer.ts` and `goal-reached.producer.ts` carry no sales gate. They skip such a goal and count it. Every run logs the count; a run that sends nothing also names it in `withheld_reason`, which by its table's comment carries only a no-op's sentence. Claim `A-GOAL-PRODUCERS-SKIP-SALES-GATED-GOALS` pins the skip. **Closes with** `fix/goal-producers-tell-only-sales-holders`, which hands them the gate for sales holders and retires that claim.

## The insight feed carries no days-of-stock goal's pace, for any role — OPEN — 2026-11-01

Every role reads `analytics_insights` (ADR 0348, GET `insights`), so `computeGoalsFamily` writes no pace for a sales-gated goal. An owner loses it in the feed too, and reads that pace on the goal itself, through the gated goal routes. Nothing is lost for good: `computeGoalsFamily` computes the pace from the goals at each generation, so the follow-up's next run writes it. ADR 0298 decision 9 (`0298-…md:70`) records this interim and its rejected alternative, a read-time per-viewer filter; this entry closes with ADR 0348's post-#617 follow-up. Claim `A-INSIGHT-FEED-SKIPS-SALES-GATED-GOALS` pins the skip, and that PR retires it. That PR also edits `days-of-stock-goal-feeds.spec.ts`, which today expects a `wine_revenue` goal in recommendations for a viewer without sales. The skip needs the row's `metric_key`: the claim also requires that the insight bundle's goals query and `listGoals` select `*` or name the column, and `isSalesGatedGoal` counts a row without its key as gated.

Rows written before this deploy are not re-gated, but a generation deletes each refreshed category's rows before it inserts (`insight-generator.service.ts:778-783`), so a goals pace written before deploy goes at the next goals refresh. Other readers of `analytics_goals` (the agent orchestrator, mobile, any later route) carry no gate; the closing PR enumerates them. The gate is application-side, with no RLS behind it. A read-only query at 2026-11-01T17:45:09Z (`select count(*) from analytics_goals where metric_key='days_of_inventory'`, and the same over `analytics_insights` where `category='goals'` and the evidence names `days_of_inventory`) returned 0 and 0, out of 1 goal (`checks`) and 1 goal insight. The closing PR re-runs it at deploy rather than trusting this count, since a row written between now and the deploy would stay readable.
