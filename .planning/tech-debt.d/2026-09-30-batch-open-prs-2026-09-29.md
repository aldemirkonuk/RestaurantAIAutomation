## The deploy own-run guard does not hold four known evasions — OPEN — 2026-09-30

Filed from the ADR 0090 audit of #534 (round 3, Opus final say at `abf660e14`), on the founder's pick, verbatim: *"Honest record (Recommended)"*. `scripts/check_deploy_own_pushes.py` (gate-owned) holds `deploy.yml` to this repository's own CI runs on main, a push or a manual run (ADR 0097, 2026-09-30 amendment). Its self-test plants 52 breaks. These four known evasions pass it:

1. **A job-level key before the refusal step.** For example, `concurrency: |` placed before "The run is this repository's own push or manual run on main" turns the steps after it into that key's string value, so `ci-gate` would stay green on a fork run.
2. **A column-0 comment inside `on:`.** It ends the guard's `on:` read, so a trigger added after it is not compared with `ON_BLOCK`.
3. **A job-level `env: BASH_ENV` on `ci-gate`.** It is not pinned.
4. **A `GITHUB_PATH` write in a `ci-gate` step.** Only `GITHUB_ENV` and `GITHUB_OUTPUT` are refused.

**Why runtime still holds.** Every stage's and `deploy-audit`'s job-level `if` independently requires the own-run group, and the guard pins those `if`s exactly. None of the four changes a job `if`. Each also needs an edit to `deploy.yml`, which is gate-owned, so it would face an ADR 0090 audit and the founder's sign-off.

**The fix.**
- Require `ci-gate`'s `steps:` sequence to run unbroken, with no job-level key between steps.
- Read comment lines as part of the `on:` block.
- Pin `ci-gate`'s job-level keys (`env`, `container`, `runs-on`).
- Refuse `GITHUB_PATH`.
- Plant each of the four in the self-test, then update ADR 0097's "Not held" list, the claim `DEPLOY-RUNS-ONLY-ON-OWN-PUSHES` and this entry.

**Severity:** low while open. This is defence in depth; the stage `if`s carry the protection.
