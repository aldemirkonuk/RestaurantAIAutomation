## A written 750 ml is not proof of a stated bottle size — OWED elsewhere — 2026-10-07

`AddWineToInventoryModal.tsx` starts its bottle-size field at 750 (`useState<number>(750)`, `:98`) and sets it back to 750 on close (`:167`). Choosing a wine does not change it (`handleSelectWine`, `:182`). The modal always sends the field (`handleAddToInventory`, `volumeFields.bottleSizeMl`, `:196-197`). /inventory's caller passes it on (`InventoryCommandPage.tsx:1682`, `bottleSizeMl: volumeFields?.bottleSizeMl`). The gateway writes it whenever it is present (`inventory.service.ts:1003-1004`, `insertData.bottle_size_ml = dto.bottleSizeMl`). So a row added through that sheet holds 750 whether or not anyone stated a size, even when the library lists the wine at another size. This is the pattern [ADR 0116](../decisions/0116-a-threshold-stops-an-order-and-a-default-is-not-an-answer.md) names in its title, "a default is not an answer". ADR 0116 itself dropped three column defaults and does not name `bottle_size_ml`. It changes no count under ADR 0299 rule 1: a stated 750 and the form default are both read at 750. It does mean `bottle_size_ml = 750` cannot be counted as a stated size, by a "size is missing" line or by a size audit. Owed in the add-wine and bottle-size work (ADR 0115, AW15), not in this PR, which touches no web inventory file. Not measured: how many production rows hold a form-default 750 (no production read).

## The insight's sealed count is not the register's — OPEN — 2026-10-04

## The open-ml reads keep one rollup row per inventory row and read one page — OPEN — 2026-10-06 [2026-10-07: the one-page half is FIXED; the duplicate-row half is still OPEN]

`inventory_lot_rollup` groups by `inventory_id, restaurant_id, master_wine_id` (`supabase/migrations/20260902150000_lot_cost_truth.sql`, the view's `GROUP BY`). The register (`analytics.service.ts`, `loadInventory`), Wine-360 (`advanced-analytics.service.ts`) and the insight's `readOpenMl` (`insight-generator.service.ts`) all key the rows by `inventory_id` and keep the last one, so `open_ml` is that row's, not the sum; the register and Wine-360 already did this for the sealed count. None of the three reads is paged, so a house with more rollup rows than `max_rows = 1000` (`supabase/config.toml`) reads part of it. Both were noted in the review of #619 and left as residuals.
