## Decisions taken in the server half, and what they leave — OPEN — 2026-11-07

- **AVIF is refused too, by its own name.** Only the major brand at bytes 8-11 is read, so an AVIF whose major brand is `mif1` is called HEIC. Refused either way; only the word differs.
- **A throw, not a returned document.** The first cut returned an unread document with `currency: ""`; the intake then ran it through `applyCurrencyRules`, which filed it in the house's currency (audit, 2026-11-07). `route()` now catches `PaperFormatRefusal` and returns its own `unreadable()` before the rules. With no model key, the intake's "no extraction model" sentence still wins, because `available()` is checked first. PR #688 edits other lines of `document-intake.service.ts` (`git merge-tree`: clean); whichever lands second re-runs both specs.
- **The bare fallback is no longer `image/jpeg`.** Two shapes that used to reach the model and fail there are now refused with a reason: a PDF with bytes before `%PDF` and no `pdf` in its declared type, and a `text/*` invoice that is not X12. Not measured: stored papers of those shapes were not counted.

## Wave 2: the menu scan and the pickers — OPEN — 2026-11-07

Every fork here was the session's call under the founder's /goal of 2026-11-07.

- **One sniff.** `apps/api-gateway/src/common/photo-format.ts` now holds the byte sniff and the refusal wording; document intake and the menu scan both use it (`claims.d/fix-photo-arrives-readable.jsonl:2`). The menu scan used to fall back to `image/jpeg`; a HEIC, AVIF or unknown-format menu is now a 400 before any model call, reading "…so nothing was imported." The reason and remedy are worded once; only the outcome clause differs, because a refused menu is not stored.
- **A `data:` URL prefix is looked past**, and both readers send the model the bare base64. Not done: `menus.service.ts` still decodes the raw payload for the kept source file, so a prefixed menu that is read would keep wrong bytes. No client sends a prefix today (each strips it before upload).
- **`.heic`/`.heif` left the web accept list.** Sources: Safari 17+ hands over JPEG/PNG picks converted *to* HEIC when the accept list names `image/heic` (developer.apple.com/forums/thread/743049); iOS Safari sends the photo library as JPEG whatever the accept value (zenn.dev/link/comments/c356d4558e16ad, community test); WebKit bug 292350 (converts to the first listed type). Not checked on a real iPhone, and whether the `.heic` extension token triggers the same conversion as the `image/heic` MIME was not tested. A desktop HEIC still reaches the server via "All files" and gets the refusal.
