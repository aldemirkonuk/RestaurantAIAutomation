# Quick Task 260401-x24: Haiku vs Sonnet Benchmark — Summary

**One-liner:** Live benchmark on 10 Chicago restaurant menus showed Haiku matches Sonnet extraction quality at 3.8x lower cost ($0.13 vs $0.49/restaurant), making Haiku the recommended model pending one MAX_TOKENS=8192 re-run.

## Key Findings

### Model Comparison

| Metric | Sonnet (claude-sonnet-4-20250514) | Haiku (claude-haiku-4-5-20251001) |
|--------|----------------------------------|----------------------------------|
| Avg field completeness (all pages) | 0.2762 | 0.2915 |
| Avg field completeness (wine pages only) | 0.6905 | 0.7288 |
| p50 latency | 25,378ms | 12,209ms |
| p95 latency | 51,472ms | 23,436ms |
| Total cost (10 images) | $0.3241 | $0.0861 |
| Est. cost/restaurant (15 pages) | $0.4862 | $0.1291 |
| Parse errors | 2 | 2 |
| Wines extracted | 93 | 93 |

### Parse Error Root Cause
Both models hit exactly 2 parse errors on the same 2 AVEC images. Root cause: `MAX_TOKENS=4096` in the benchmark caused output truncation mid-JSON. The production extractor uses `MAX_TOKENS=8192`. These are infrastructure artifacts, not model quality failures.

### Field Completeness on Wine Pages
Both models extract the same wines with comparable fill rates. Haiku is slightly better on `country` (100% vs 82%). Low `vintage` scores (18–19%) are expected — the tested menus are mostly by-the-glass lists without vintages.

---

## Recommendation

**Switch to Haiku — conditional on one re-run with MAX_TOKENS=8192.**

Haiku is 3.8x cheaper and 2.1x faster at p50 with no quality degradation on this menu set. At $0.13/restaurant it comfortably beats the $0.50 cost target. Sonnet at $0.49/restaurant is borderline.

**Required action before switching:**
1. Re-run `scripts/benchmark_haiku_vs_sonnet.py` with `MAX_TOKENS=8192` flag (or edit constant)
2. Confirm parse_error_count drops to 0 for both AVEC images
3. Update `claude_vision_extractor.py`: `MODEL_ID`, `PRICE_INPUT_PER_M=0.80`, `PRICE_OUTPUT_PER_M=4.00`
