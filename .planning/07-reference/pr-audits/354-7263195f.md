## 1. Correctness & regression risk — BLOCK

**`services/agent-orchestrator/scripts/cascading_report.py` — a fourth wave-letter
structure this PR's sweep missed.** The PR correctly removed D/E/G from the wave-letter
maps in `conftest_prod.py` and `report_generator.py`, but a third, separate map in this
file (`wave_files`, `WAVE_DEPS`, `SUGGESTED_FIXES`) still named all three retired waves.
`collect_wave_results` treats a missing JUnit XML as `status: "missing"`, and
`find_failed_waves` counts `"missing"` as failed. The auditor reproduced this live: with
synthetic green `wave_{a,b,c,f}.xml` files (simulating the surviving waves passing) and
no `wave_d/e/g.xml` (since the retirement no-op step never writes one), the script
printed:

```
[cascading_report] ⚠️  Failed waves: ['D', 'E', 'G']
  Root cause: Wave E
  Fix: Gmail failure (Wave E) cascaded to Calendar (Wave G). Fix GMAIL_USER/GMAIL_PASSWORD on Railway orche...
```

The uploaded `cascading_report.md` artifact would permanently instruct a future reader
to set Gmail credentials and re-run the deleted files against production — the exact
two actions ADR 0137 exists to prevent. Nothing in CI catches this: the step is `|| true`
and the deploy gate globs only existing XMLs, so the job stays green while the artifact
is silently wrong. This is "absence reported as illness," the inverted shape of this
repo's own named cross-cutting fault, introduced (not merely left in place) by this PR
— the pre-PR behavior was differently wrong (a skipped wave's JUnit XML reads as
passed), not this specific false-failure shape.

## 2. CLAUDE.md-and-ADR compliance — BLOCK

**Independently found the same `cascading_report.py` gap**, plus a second, distinct
defect: **a stray blank line in `.planning/decisions/README.md`** detaches the new 0137
index row from its table. A blank line terminates a GFM/CommonMark table, so the row
would render as a plain paragraph of pipe-delimited text, not a table row, in the
repo's own primary decision index — a file CLAUDE.md §1 names as one of four doc entry
points "in reading order."

Both findings are CLAUDE.md §0.5 violations of the same shape: "Reporting a partial
result as complete is the one unrecoverable failure here." ADR 0137's own "Cleaned up
alongside the deletion" list asserted a complete sweep of "each reference" while a
third map and a rendering defect sat unmentioned.

Everything else checked out: the decision is within the founder's authorized menu
(repoint/delete/gate), the ADR matches `TEMPLATE.md` section-for-section with an honest
`Proposed` status, every re-derivable count in `EXISTING-TEST-INVENTORY.md` matched
exactly, all wikilinks resolved, the ADR number is uniquely claimed (swept across
worktrees), the co-author trailer is correct, and no scope creep beyond the D/E/G task.
