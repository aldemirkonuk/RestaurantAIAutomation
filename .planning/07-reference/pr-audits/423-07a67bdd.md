## Other findings (both reviewers; none blocking on their own)

- **A peer's suggested workaround does not work.** Rewriting the token source with capturing groups
  (`/((reset-password|verify-email)(/.*)?|...)`) is refused by `path-to-regexp@6.1.0` ("Capturing groups are not allowed": a nested `(` must be
  `(?`), so it would fail `vercel build`. The lint added in this PR refuses exactly that shape.
- ADR 0158 says "One difference remains: a literal `.`". Not the only one: a modifier after a group is read differently by path-to-regexp
  (it applies to the preceding `/` and the group: `/(a)?` matches the empty path, not `/`; `/(a)*` is `^(?:\/((?:a)(?:\/(?:a))*))?$`), and a unit
  test asserts `['/(a)*', '/aa']` matches, which the library does not. Nothing in the repo triggers it.
- The rejection lists in the ADR and the live-check CLAIMS row omit "a top-level group starting with `?`" (`/(?:a|b)`, `/(?!x).*`), the most
  natural way to write an exclusion; ADR item 6 should say to wrap the lookahead in a capture group, and that the prescribed lookahead leaves prefix
  paths such as `/reset-passwordx` (not routes: 404) uncovered.
- Guard-model edges, all exotic: `:[A-Za-z_]` misses a digit-named parameter (`/a:1` is a real parameter) and `/a:` (a missing name the library
  refuses); a `)` inside a character class (`/([)])`, `/a[){]`) defeats both scans; the docstring's "nothing this accepts is refused" is slightly broad.
- The ADR says #418 has not landed; it has, and the duplicate project's live alias still answers the token routes with `x-robots-tag: noindex` and
  no `Referrer-Policy` (its redeploy has not shown yet).
- `it.only` on another test is not caught by the CLAIMS grep (vitest's `allowOnly` covers it in CI).

## What held

The new source compiles (`@vercel/routing-utils@6.6.0`, `path-to-regexp@6.1.0` and `6.3.0`) to
`^(?:\/((?:reset-password|verify-email)(?:\/.*)?|invite\/.*|studio\/invite\/.*))$`, matches all ten token paths and none of the negatives,
and the whole file transforms with no error, before and after. It never overlaps #418's lookahead rule. The census fails on production on exactly
the four unmatched samples and passes the other six; the self-test passes; claims 403/403. Every mutation in the bundle turned a check red
(`it.skip` only the CLAIMS row, as claimed). The lint was fuzzed against the real library (about 105,000 sources; 4.3 million strings up to length
5): no false positive, and no false negative in the modelled domain. The cross-origin claim holds in the deployed bundle (`ee=H6()` uses the
absolute gateway URL; `ResetPassword` posts to `HX`). The census and self-test leak nothing.
