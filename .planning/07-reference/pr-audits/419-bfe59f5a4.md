## BLOCK finding (security)

Staff members who open `/settings` after always-on cutover trigger `useSettingsNextData()` at `SettingsNext.tsx:160` **before** the staff UI gate at `:213`.

The interview redesign removed the `active` section parameter, so every tenant register fetches on mount (`useSettingsNextData.ts:531-534`), including `GET /calendar/ical-token`. That controller (`calendar.controller.ts:811-823`) is JWT-only — no owner/manager role check — and `getOrGenerateICalToken` **returns or mints** `restaurants.calendar_ical_token` (the unauthenticated feed credential).

On `origin/main`, `useSettingsNextData(active)` only keyed a fetch when `active === section`, so a default `/settings` load did not pull the calendar token. Always-on expands this to every house's staff.

CI asserts the "Ask a manager" UI (`SettingsNext.test.tsx:506-510`) but does not assert that network fetches were skipped.

**Fix shape (not applied this session):** skip tenant remotes when `role === 'staff'` (or gate before the hook), then re-audit.
