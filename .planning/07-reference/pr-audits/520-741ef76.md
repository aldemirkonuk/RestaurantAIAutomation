## The coordinator's challenges
1. **Silently dropping a claim by blanking a legacy row or turning it into a `_comment` row.** Both reviewers reproduced it. I checked whether main already allows it. It does: base `_claims_parse.py:54-55` skips blank lines and `:72` skips any object with a `_comment` key, and base `check_decision_claims.sh` has no claim-count floor. So on main, deleting, blanking or commenting out a row all pass silently. The PR makes nothing worse: outright line deletion now fails with exit 7, and blanking is no more open than before.
   Does the ADR overclaim this? ADR 0240:42 ("Deleting a legacy row now means editing the pin ... since a deletion shifts every citation below it") and claims.d/README.md:13 ("deleting a row fails the build") are true of removing a line. They are the guarantee the ADR sets out to give, which is that line citations stay stable, and blanking keeps that. Blanking a row is also a kind of in-place edit, which the ADR explicitly permits (ADR:34). In-place edits could always neuter a claim (for example `verify` set to `true`), and review is the only check on them, on main and after this PR. The wording is still incomplete: ADR:43 names one known hole (delete one row and add one) and leaves out blanking and `_comment`. That is a documentation gap, not a report of partial work as complete, and it does not weaken CI. **Not a blocker. Follow-up:** add the hole to ADR:43 and the README, or apply the adversary's cheap hardening (sentinel-only `_comment` in the frozen file, or pin the claim count at 744).
2. **Changing the pin and appending in one diff.** Confirmed: it passes CI. The pins live in check_decision_claims.sh, which is not gate-owned. That was already true of the whole runner, which any PR could edit before this PR. The runner comment and the ADR both say changing a pin is deliberate and shows in review. The freeze is a merge-conflict and citation-stability mechanism, not a security control. No regression.
3. **The dropped PR-B claim row vs CLAUDE.md §5b.** The draft's `open` claim ("CLAUDE.md names claims.d/") could be checked by a command, and §5b says to write such claims as commands, so dropping it is a real deviation. It is disclosed at ADR 0240:73, and ADR:75-80 lists PR B's exact edits. It does little harm: a session that follows the stale CLAUDE.md:167 gets exit 7 with a message naming claims.d/ (check_decision_claims.sh:145-149), so the mechanism corrects the mistake itself. **Not a blocker. Follow-up:** file that `open` row in a claims.d fragment, either before or inside PR B, so PR B cannot be forgotten silently.
