## Adjudication of R1 (lost reply / timeout -> duplicate vendor)
I tried to overturn on two grounds.
(a) New UI copy overclaims. "There is no connection, so the vendor is queued and will be added"
  is false on a 30s timeout (client.ts:66) or a reply lost after the server committed. In that
  case the replay 100ms later (sync-manager.ts:192-194) creates a second row: there is no
  idempotency key, no duplicate check on the custom branch, and no UNIQUE constraint (adversary).
(b) For a create with no reply, the D10 "check the book, it may already be there" wording is
  unreachable.
Both are real. They do not overturn:
- On main 2ba1326e3/aca12b244 the same no-response case was also queued and replayed. So was every
  4xx and 5xx. On main the sheet then wrote rating, delivery days and address against a temp id and
  told the user those were recorded. The D10 branch was unreachable for every failure on main, not
  only for a missing reply.
- Every failure class moves toward the truth; none moves away. The duplicate is not new, and its
  trigger set strictly shrinks.
- ADR 0140 ("claims nothing it cannot prove") binds the door outbox, not this hook, and no locked
  decision is contradicted.
- A BLOCK would keep main's worse behaviour: a fake "saved offline" on every 400.
My plan's framing of R1 as a possible blocker was too strong. The right call is non-blocking with
a disclosed follow-up.
