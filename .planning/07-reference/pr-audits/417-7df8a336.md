## What the first run found and how this run answered it

`resolved` CLAIMS row saying the guard "fails on any rule that matches a token route and disagrees, wherever it sits". That is

## Findings (all non-blocking; the planner's ruling on each is in the last section)

- **Live gap, pre-existing (#385), reproduced independently by both reviewers, the planner and the author:** `/reset-password/`,
  `/reset-password/?token=x` and `/verify-email/` answer 200 on production with neither `Referrer-Policy` nor `X-Robots-Tag`
  (the HTML `noindex, nofollow` meta is present; `auth.service.ts:980` and `:2145` link the slashless forms). #417 documents and
  tracks it; it does not close it. Concrete harm class (reported by the merge-train session; not verified by this run, in particular whether gateway logs record the Referer): the
  browser default `strict-origin-when-cross-origin` sends the full URL in the Referer of same-origin requests, so on this host
  an `/api/*` call could carry the token into gateway access logs; it needs a trailing-slash token link the product does not
  generate.
- Open row: a JS-valid but Python-invalid source (`(?<t>...)/?`) raises `re.error` in the row's verify at exit 1, which reads as
  "still open"; a `:name` source is caught loudly by vitest, this shape is not; the phrase "however the fix is shaped" reaches
  past that. Disclosed in the claim and the ADR; a stale *open* prompts re-checking and never asserts absent protection.
- The `resolved` row's verify is presence greps; two mutations still leave it green (`header_map` reduced to last-wins with the
  call kept; the `policies ==` predicate replaced by `True`), and `it.skip` on the new test is invisible to both gates. The
  behaviour is true (fixture harness), but no committed test runs the census.
- ADR item 6 says a site-wide `X-Robots-Tag` "must not match the token routes" while the shipped `/(.*)` missing-host rule does
  and the guard permits it (stricter than the code, so not misleading); it does not say "in `apps/web/vercel.json`"; and it
  prescribes a lookahead without saying the UNNAMED form (`/((?!...).*)`) is the one the guard can read.
- The census reads `X-Robots-Tag` as a superset and probes the base host only; the duplicate Vercel project
  (`restaurant-ai-automation-api-gatewa.vercel.app`, repo-root `vercel.json`) serves token routes with `x-robots-tag: noindex`
  only and no `Referrer-Policy`, which ADR 0158's unconditional wording does not reflect. PR #418 adds a token rule to that
  file; it is pre-existing and off the emailed host.
- Tag-along `pr-audits/388-32dcaff2.md`: follows the #388 precedent; the hook reads PR comments only, so its embedded
  `pr=388` marker satisfies nothing here; a minor CLAUDE.md §2 blemish and `07-reference/INDEX.md` has never indexed

- The ADR's "Sources" limit names "a bare `*`" as a silent mis-evaluation. **Measured false example:** `path-to-regexp@6.1.0`

  match-everything source that the guard reads as literal braces.

## What held

split and duplicated fields correctly, fails a 404 or a 308, and leaks nothing (no auth headers, synthetic tokens, no `Location`
or body printed). `header_map` is benign for redirects and `HTTPError`. Sibling PR #418's added rules neither invalidate a CLAIMS
row nor an ADR sentence (its Referrer-Policy lookahead also excludes `/reset-password/`; it does not touch the token rule).
The gate's marker in the tag-along file cannot satisfy any merge gate (`require_pr_audit.py` reads PR comments and requires
the PR number and head SHA to match).

## The planner's matcher measurement (addendum)

The merge-train session (`restaurant-ai-automation-69`) reported that Vercel compiles sources with the case-insensitive flag,
that a bare `*` is not a hole, and that `{...}` groups are. The author checked; the planner re-measured from the source. Result:
`@vercel/routing-utils@6.6.0` compiles sources with `pathToRegexp(..., { strict: true, sensitive: true, delimiter: "/" })`
(`dist/superstatic.js:266-271`). So matching is **case-sensitive** (production agrees: `/Reset-Password` answers 404 with none of
the token headers), and **strict** (no optional trailing delimiter), which makes this PR's trailing-slash diagnosis right and the
guard's regex read a faithful model for every shape shipped or proposed. The `{...}` divergence is real. A trailing bare `/?` is
not valid path-to-regexp syntax (`Unexpected MODIFIER`); a deployable widening puts the optional slash inside the capture group.
