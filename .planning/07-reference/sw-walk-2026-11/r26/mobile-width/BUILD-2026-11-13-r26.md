# r26 mobile-width — BUILD 2026-11-13

Lane: /settings is 756px wide at 375px (r24 walk, pre-existing). Find what forces it, fix it, sweep the other main routes in code. No browser and no local stack in this phase.

## Audit (code, not measured)

/settings: the layout shell is sound. The grid is `minmax(0,1fr)`, `main` has `minWidth 0`, and DashboardLayout is block. The overflow comes from inside the registers.
- **SectionKit `Row`** (every register row, about 60 call sites): `display:flex`, no wrap, words `flex:1; minWidth:0`, control `flexShrink:0`. The control is laid out at its max-content width, so a wrapping `inline-flex` control never wraps. Estimated widths:
  - DigestRow unanswered (hour 56, urgency select about 190, address 140, Record): about 480px.
  - NotifySection "Email and in-app / In-app only / Off": about 283px. This leaves the words about 40px.
  - Currency and Time zone (select at its longest option, plus Record): about 320–400px.
  - ConfirmAction when armed: about 456px.
- **`fieldStyle`** had no width cap, so a select was as wide as its longest option.
- **LedgerSection ("What changed here")**: an object value is printed as `JSON.stringify` with no spaces, in an `auto` grid column. That column grows to the string's width, so a terms change of about 90 characters reaches about 830px. This is the most likely single 756px source, but it was not measured.
- On main, `<code>` file paths (MapSection, CarryingCost, …) were long unbroken words. They are already gone on #1134/#1135.

Sweep of the other routes (pages/*/next, components/mudavym, documents):
- Every `<table>` either sits in an `overflow-x:auto` wrapper (cellar ×5, inventory, menu ×4, notifications, receipts, reports, vendor-prices, settings vendor terms, team sales) or turns into blocks at 640px (inventory paper table, canonical document).
- Fixed grids are either `auto-fit, minmax(≤240px,1fr)` or behind a media query: promotions, endpaper at 700px, team week grid in a scroll wrapper.
- AgreementSheet `90px 1fr 110px` is fine: its fields are `width:100%`, so they do not push the column wider. A draft PR for it was dropped.
- AuthShell's 640px glow sits under `overflow-hidden`.
- **Found, not fixed:** /notifications `BookRow`. When a line is folded (+N), snoozed ("back in …") and its winner is stale (two-line time), the shrink-0 pieces add up to about 455px, which is wider than 375. This is an edge case only; the common line is about 230px.
