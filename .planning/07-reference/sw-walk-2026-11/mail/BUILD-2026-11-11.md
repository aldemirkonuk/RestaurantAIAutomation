## Left, and why

- **G1 / L1:** #681 still needs its rebase. That PR belongs to its own lane, and this session did not touch it.
- **G4 / L6:** the counterpart store for guests and strangers (`house_mail`) is not built. Unknown senders are still `not_kept`. This is the biggest piece left: a migration, an RPC and a read-model change.
- **G6 / L7:** retention of raw shared-mailbox mail, including purging `mail_intake` payloads past the window, is not built. Settled rows already clear their payload, but given-up rows keep it until read again.
- **G2 follow-ups, stated in #1046 and #1049:**
  - A re-driven held or prospect letter at the inbound address can be held twice.
  - The Python agents also consume `email.events`, so a re-drive reaches them again.
  - An exception inside prospect capture reads as `not_kept`.
- **G2 surface:** no web page reads `GET letters/intake` yet. The IntakeHealthSheet (L9) is not built.
- **G9** (thread paging), **G10** (`regenerateSummary`), **G15 / L10** (notice deep links to the thread), **G16 / L11** (the dead web surface: `useConversationQueries` private axios, `ConversationApprovalNotification`, `useForceFetchReplies`): not built. Budget went to G2, which carried the data-loss risk.
- **G13:** the message-id write-side normalisation belongs to the `fix/mail-message-id-one-shape` lane (#1031/#1032). The inbound webhook's messageId preference was deliberately left alone.
- **G14:** the gateway instance count is mostly answered by the design: `claim_mail_intake` uses SKIP LOCKED and the cursor is forward-only. A per-instance `reading` flag remains, so two instances can read the same history concurrently. That is safe, because a repeat is one intake row, but it wastes quota.
- **G17 / L12:** the `.planning/08-softwares/communications-hub.md` rewrite and the ADR records for F1-F16 are not done. Under the batch rule, decisions live in the PR bodies until the batch review.
- **Overlaps left open:** #792 (`fix/gmail-push-reads-every-history-page`) and #791 (`fix/inbound-parse-door-refuses-loudly`) are both on main and are covered by #1047 and #1049. They were not closed, because closing PRs is not this session's call.
- **Not verified:**
  - The migration has never been applied to a real Postgres; only fakes were used.
  - The Connections row was not checked in a browser, because the local stack script belongs to another lane.
  - Gmail Pub/Sub was not exercised live.
