## Decisions (the session's call, /goal 2026-11-07)

- **N2 is web only.** PATCH /menus/items/:id and the discard route already
  enforce owner/manager, the price rules and non-empty values. Rejected: a batch
  correct endpoint, which would be a second write path for the same rules.
  Each changed field is sent in order, and a partial save is said ("The bottle
  price was not corrected: … The name was corrected.").
- **Dish vs drink is decided once, in the shared read** (current-menu-lines.ts,
  used by recipes, cellar and beverages). Rejected: adding columns per caller
  (three copies of the rule), and a second read in the recipe lane. The change
  is split, because #1503 has the old 2-arg isKitchenLine: #1597 on the menu
  train, #1598 on the recipe chain with a fallback.
- **Price history has its own controller** (PriceHistoryController), so the
  hand-built PricingController specs stay untouched. It is owner/manager only,
  as "who set it" is in the plan. Newest 30 plus `more`, rather than unbounded
  (1000-row cap) or paged UI (no one has asked for page 2 yet).
- **The web client is a new file** (services/api/priceHistory.ts) to avoid
  conflicting with open pricing.ts PRs (#1381).
