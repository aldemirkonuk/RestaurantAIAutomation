## What each PR does

- **#1580.** The counter's "Vendor replies waiting" register used to count `procurement_conversations.delivery_status='pending'`. No writer sets that value, so the count was always 0. It now reads `MailService.waitingVendors`, the same `mail_inbox_summary` and `list_mail_people(waiting_only)` that the Mail tab reads, so the two numbers agree.
  - Each row reads: vendor · order N · waiting for the house's reply.
  - A row opens /communications?tab=mail&with=vendor:<id>. The register itself opens /communications?tab=mail.
  - Bare /communications still opens Letters, because about ten links rely on that.
- **#1587.** Staff (canReply false) were told "waiting on you" about mail they cannot answer. The header, the empty-list words, the search-empty words and the chip now say "the house" to staff. Owners and managers still read "you".
- **#1599 + #1603.**
  - Problem: a connected house mailbox with no vendor email address in the book read as healthy but silent.
  - Gateway: with an empty book, the cursor is now seeded at consent, so reading starts from then. GET /communications/letters/sender `reader` carries `bookAddresses`: the live count of distinct vendor addresses, or null when it cannot be read.
  - Web: when the count is 0, the status line says so, and owners and managers get an "Add a vendor's email address" button that opens /vendors.
- **#1608.** A vendor letter on no order now also writes a bell notice.
  - Type `vendor_reply`, so it files under "Vendor mail"; priority low.
  - Recipients: owners and managers.
  - It opens the thread in Mail.
  - One notice per thread per house while it is unread.
  - Bulk, list and auto-submitted mail is skipped.
  - If the unread check fails, it rings anyway.

## Decisions (the session's call, 2026-11-07 goal)

- **Counter source (#1580).** Reuse MailService. Rejected: keep `delivery_status` and add a writer, since that would be a second definition of "waiting". Rejected: a new RPC, since that would duplicate `mail_inbox_summary`.
- **Counter link (#1580).** Fix only the counter's link to `?tab=mail`. Rejected: make bare /communications open Mail, since about ten links mean Letters. Sidebar.tsx was not touched, because four onboarding PRs own it.
- **Empty book (#1599).** A live `book()` count on each status read. Rejected: a stored outcome column plus a migration, since it would stay up to 5 minutes stale after the first address is added. Seeding the cursor at consent keeps the consent promise ("letters from then on").
- **Bell audience (#1608).** Owners and managers. Rejected: the whole house, because staff cannot reply.
- **Bell de-duplication (#1608).** One unread notice per house per thread.
  - Rejected: no de-duplication, because a ten-letter thread would make ten rows.
  - Rejected: a per-person check, because it would change the shared `persistManagerNotification`.
  - Known cost: once one person has read the notice, a later letter on the same thread does not ring the others again. The toast and the Mail count still show it.
