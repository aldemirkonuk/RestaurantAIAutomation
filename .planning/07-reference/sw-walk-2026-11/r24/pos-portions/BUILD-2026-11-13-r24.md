# r24 pos-portions: the POS panel's sale sizes follow the good

## Audit (evidence, at #1296 c2272cc48)
- `PosMappingPanel.tsx:487-495` offered `Glass {pourMl ?? 150}ml` for every candidate, a soda included. `pourMl` was the mapper's `row.pour_size_ml ?? default_pour_ml`. Both columns have a DB DEFAULT of 150 (ADR 0193 F7; `20260922230600_a_house_confirms_its_pour_before_glass_advice.sql:10`).
- An unsized wine read 750 from the mapper's `master_wine_library.bottle_size_ml ?? 750` (inventory.service.ts:89). The library column is `NOT NULL DEFAULT 750` (baseline:3521), so a stated 750 cannot be told from the default.
- `record_glass_pour` (`20261222100000…sql`) reads only `COALESCE(ri.bottle_size_ml, 750)` and treats lot qty as containers. A pour is right only for a good kept by the bottle or keg, with its OWN size.
- `resolveSaleVolume` (pos-hub.service.ts:470-516), step 2: label `bottle` with a NULL volume becomes `whole_bottle`, a unit move that reads no size. #1296's reason for disabling the unsized bottle ("would queue every bottle sale") does not hold. Step 1: a stored volume ≠ the current size becomes a part pour. The #1296 answer `sale_volume_ml = size` therefore goes stale if the size is corrected.
- The old "Bottle 750ml" on a row kept by the case booked as `whole_bottle`, because 750 equalled the stand-in, and so removed one CASE per sale.
- A library-path insert defaults `kind = 'wine'` (ledgers_key.sql:431), so a library gin row may say wine. Its library `beverage_kind` says spirit.

## Calls (full text in the PR bodies)
1. A whole container is `sale_unit 'bottle'` with a NULL volume, and it is enabled when the size is unknown. The button says "· size not known". Rejected: the size as the volume (goes stale); disabling (#1296's reason does not match the code).
2. A whole container is offered only for uom bottle or each. case, pack, ml, g and glass get no offer, plus a note.
3. A pour needs the row's own bottle size. The library size does not count, because the RPC never reads it.
4. A pour needs a confirmed pour: the item's own, or the house's for a wine only. Never the 150 default, and never the wine pour used as a shot.
5. Kinds:
   - soft_drink and non_alcoholic: bottle or can;
   - wine: bottle or glass;
   - spirit, whiskey and liqueur: bottle or shot;
   - beer: bottle or can, or a glass off a keg;
   - sake and cider: bottle or glass.
   A library `beverage_kind` beats the trigger's 'wine' default.
6. The house's pour is read from /pricing/target-margin, not joined into 12 inventory selects. That keeps the blast radius off the inventory read.
7. The stored label is `bottle` for a can or a piece, because the gateway derives no other whole-unit word.
