## The session's call on gaps 1+2 (2026-11-07 /goal), and a Sonnet brief

**Call.** A house letter carries Reply-To set to the house's Mudavym address whenever that address exists. The dispatcher stores the Gmail `threadId` and a Message-ID that we mint, `<uuid@domain of the From>`. When the house has no Mudavym address and its sending mailbox is not read, the composer says before Send that a vendor's answer will go to that mailbox and will not be seen here.

Rejected alternatives:

- Block Send unless the placement is `whole_conversation_here`. That stops a day-1 owner from answering anyone.
- Set Reply-To only when the mailbox is not read. Read state changes over time, and a letter's Reply-To cannot change after it is sent.
- Fetch the Message-ID back from Gmail after the send. That costs an extra read on the send-only grant, which its scope refuses.

**Brief (one PR, stacked on #1397 or a later W PR owning house-letters.service.ts; the newest is #1394's tree up to the tip):**

1. `sendThroughGrant` (`house-letters.service.ts:2067`):
   - Add a `messageId` param. Write `Message-ID: <id>` with the same header helper as In-Reply-To.
   - Return `{ id, threadId }` from the JSON. Update the one caller.
2. Dispatcher (`:1786-1811`):
   - Mint `<${randomUUID()}@${domainOf(from)}>` before the send and pass it.
   - Pass `replyTo` = the active `restaurant_inbound_addresses.address` for the house. Read it plainly and never provision it (see `mail.service.ts:565-572`). Pass it only when the address exists.
   - In the SENT update, write `message_id`, `gmail_thread_id` = the returned threadId, and `email_headers.reply_to`.
3. Specs (jest, `src/communications/letters`). One test per point:
   - The MIME carries Message-ID and Reply-To.
   - With no address, there is no Reply-To.
   - The update writes `message_id` and `gmail_thread_id`.
   - An unreadable address read sends without Reply-To and logs; it never blocks the send.
   - Mutation-test the specs.
4. Words, in a second PR on the W web tip:
   - In `ComposeSheet`, when `sender.kind === 'house_mailbox'`, the house has no Mudavym address and the conversation `where !== 'whole_conversation_here'`, show one line above Send: "A vendor's answer goes to <address>, which Mudavym does not read, so it will not show in Mail."
   - Fix `house-sender.service.ts:621-622` to say the same in the house's words.
5. The gateway `tsc --noEmit -p tsconfig.json` passes, ignoring TS2307 for @simplewebauthn/server. DRAFT, at most 15 files and 30K. Browser check, on the local stack only: send a reply from Mail, answer it through the Mudavym address with In-Reply-To set to the stored Message-ID, and expect one thread.
