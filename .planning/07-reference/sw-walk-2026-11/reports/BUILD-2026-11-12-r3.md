## Built

- **#1131**
  - `loadInventory` reads every active row through `readWholeWindow`, or refuses.
  - The lot totals (`inventory_lot_rollup`) come through a new `common/read-by-ids.ts`. It asks for the inventory ids already in hand, 100 per request and 4 requests at a time. Any failed batch refuses the whole read, and so does any batch that comes back holding 1,000 rows.
  - `loadDeliveredOrders` is read whole too.
  - Added `common/testing/capped-postgrest.ts`, a stub that caps every response at 1,000 rows as PostgREST does.
- **#1132**
  - The same paging in the advanced lenses: `loadInventoryWithCost`, `loadOrders` and the seasonality wine-type map. A failed type read logs and files the wines under "unknown".
  - The goal `purchase_spend` reader is read whole.
- **#1133**
  - `recordReading` writes only when the stored `current_read_at` is null or older than the new reading. It does this inside one UPDATE: `.or(current_read_at.is.null,current_read_at.lt."<iso>")`.
  - The reading's time is taken before the metric read starts. So a slow refusal can no longer overwrite a newer success, and a slow success can no longer overwrite a newer refusal.
- **#1134**
  - Settings no longer prints `ANALYTICS.CONTROLLER.TS:…` or similar labels. The digest, carrying cost, currency, hours, map, thresholds, notify and ledger sections now say in house words who reads each setting.
  - The file:line citations moved into code comments.
- **#1135**
  - The same fix in the features section and in the cellar's reasons for leaving a column out, which used to name a migration file.
  - A new guard, `apps/web/src/no-page-names-a-source-file.test.ts`, fails if any text a page or component can render names a `.ts`, `.tsx`, `.py` or `.sql` file. It reads the code the way the compiler does and checks only on-screen text.

Decisions are recorded in each PR body as the session's call under the 2026-11-07 /goal.

- **Refuse, never serve a part.** The rejected alternative was returning the rows read so far. This follows ADR 0292 fork 3.
- **Read the lots by id rather than paging the view.** The view has no unique key: `inventory_id` is nullable, and a lot's wine can differ from its inventory row's.
- **Compare-and-set in the database.** Rejected alternatives: an in-process lock, which does not hold across gateway instances, and a version column, which would need a migration.
- **Citations in code comments, not on screen.** Rejected alternative: hiding them behind a debug toggle.
