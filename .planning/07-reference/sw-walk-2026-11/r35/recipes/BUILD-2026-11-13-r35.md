## Decisions (the session's call, under the /goal of 2026-11-07)

1. **Gap 7: which weight priced a line.**
   - **Call:** the gateway names the weight it used (`weighed`). The web shows it and does not re-derive it.
   - **Rejected:** the web recomputing which bridge applies. That would be two copies of the rule in `baseUnitCost`, free to drift apart.
2. **Gap 7: what the change box starts with.**
   - **Call:** the box starts empty, and the current weight is shown beside it ("Now 60 g.").
   - **Rejected:** prefilling the current weight. `readQty` refuses "1,125" as ambiguous, so a prefilled 1.125 g could not be kept unchanged.
3. **Gap 2, slice 2: where the menu-price offer sits.**
   - **Call:** in the opened row, never in the table cell. A bottle and a glass price are each offered separately. The offer is hidden while the cocktail Amend form is open.
   - **Rejected:**
     - a one-click "Use" in the cell, which writes a price without a confirm;
     - picking one of two menu prices automatically, which is a guess.
4. **Gap 5: what the usable share belongs to.**
   - **Call:** a share per recipe line, versioned with the line. NULL is all of it. Nutrition stays on the written amount, because what is eaten is what is plated.
   - **Rejected:**
     - a share per good: a lime used as a wedge and a lime used as juice yield differently;
     - a default yield table: it would be a guess presented as a figure;
     - a share on uncounted lines: nothing is costed there.
5. **Gap 5: a stored share that is out of range.**
   - **Call:** the line's cost is unknown and the dish incomplete, never priced. The database CHECK makes this unreachable today; the rule is defence in depth.

## Adversarial pass on gap 5 (what was tried)

- **A 64.1 % share.** 64.1 × 100 is inexact in floating point. The strict-equality decimal check refused it, so the check now allows a 1e-6 tolerance. A test pins this (mutant G14).
- **An untracked line at 100.** The SQL maps 100 to NULL and accepts it, and the gateway matches. Any other share on an untracked line is refused in both the SQL and the gateway.
- **Other cost readers.** On this stack, only `recipes.service` (sheet and preview) and `dishes.service` (list) call `recipeCost`. No SQL on this stack draws stock from `recipe_lines` (git grep `qty_base` over the migrations finds only the two recipe-save migrations and this one).
- **A web re-save drops a share. KNOWN, not fixed.** The web has no `usablePct` today. The share can only be set through the API, and a later save from the web sheet sends none, which drops it. The web brief below has to fix this.
