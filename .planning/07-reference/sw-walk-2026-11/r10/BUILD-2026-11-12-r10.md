## The session's calls (full text, with rejected alternatives, in each PR body)

1. **The money rule for the round.**
   1. A record's own currency (order, invoice, sighting, agreement).
   2. Otherwise the house's currency, for the house's own books.
   3. Otherwise the bare figure.
   Nothing converts. Rejected: a default currency (ADR 0117 — the original fault was `DEFAULT 'USD'`, dropped by `20260905120000_a_house_names_its_money.sql`), and the house's sign on a vendor's record, which would turn 25 EUR into 25 lira.
2. **One gateway helper, `common/money-in.ts`, byte-identical on #1193 and #1194.** Identical adds merge without conflict. It uses the web's sign rule (`fmtMoney`): the narrow sign only when it is one character in U+20A0–U+20CF. Rejected: a per-file ternary, and a shared module PR the others stack on (a stacking cascade).
3. **Dead stock names its bottle at the read, not at the card.** Fixing it in `loadInventory` also fixes the restock register and the export. Rejected: the id as a last fallback, which is what the house saw, and null, which renders "top: null".
4. **The /reports working sentences are fixed at their source, stacked on the #1187 tip.** #1156 translates them on the page, but the export (`report-export-cuttings.ts:668`) prints the basis verbatim, and the "uncosted" variant from #1144 exists only on that train. Rejected: a second translation table in the export, and leaving the export as it was.
5. **`lib/utils.ts formatMoney`: deprecate and guard; no new parameter and no provider.** The brief's "45 importers" is the count for lib/utils as a whole. Only 3 files import `formatMoney`, and #1181/#1183 own all 3. Rejected: a currency parameter (it would collide with both owning PRs) and a context provider (it would wrap the app tree for 3 callers).
6. **Not done, by evidence:**
   - `OneTapActionCenter` is rendered by no route; only its story and DevSandbox use it.
   - `WineValidationModal`'s only importer, `MenuScannerTab`, is deleted by #1068.
   - `TwinSheet:115` is already replaced by #688.
   - `invoice-match.ts` is already fixed by #1127.
   - agreed-price lines 287 and 815 are bare by #1180's own choice, and were left to #1180.
7. **`amountIn` in promo-extract is local, not `moneyIn`.** It keeps the mail's own digits (no rounding, no added decimals). Rejected: `moneyIn`, which would print "€15.00" where the vendor wrote "€15".
