## Part B decisions (the session's calls), not built

**(a) Dish recipes: GAP; the founder's core ask for foods.**
- Call: widen `recipe_versions.owner_kind` to `('cocktail','dish')`, add `dish_id` with its own CHECK, and add a `recipe_current_dish` pointer, or generalise `recipe_current` to (owner_kind, owner_id).
- The owner is a new `dishes` table (restaurant_id, name, menu price, section). `save_recipe_version` becomes owner-generic. The gateway's recipes service and controller take an owner kind. The web reuses RecipeSheet on a /dishes sheet. `ItemUsedIn` reads dish lines the same way drink lines are read.
- Rejected:
  - Storing dishes as `cocktails` rows: it mislabels food, and the drink cards (pure alcohol, glass) would apply to a plate.
  - Making menu lines the owners of recipes: lines are versioned with the menu, and a recipe must outlive a menu version.
- Shape: three stacked PRs (migration, gateway, web), each ≤15 files. The migration version must come after everything on main and in the open PRs (`check_migration_versions_unique.py`). Write the ADR first, because the recipe engine's ADR says "prep and dish widen this CHECK later".

**(b) A pasted line proposes its shelf link.**
- Call: when a pasted label equals a shelf item's name exactly (case- and space-folded), the proposal shows "Linked to X — change", and it stays a proposal until Save. F17 ("proposed only") holds because nothing is saved unseen.
- Rejected:
  - Fuzzy matching: a wrong link silently changes cost.
  - Linking at Save without showing it: the owner would not see what was linked.
- Needs: one shelf read per paste (not per line); `useShelf` takes one search string, so add a names lookup or read the whole shelf once.

**(c) Pour cost on the drink cards.**
- Call: add a "Pour cost" card (cost a serve ÷ price, shown as a %) beside Price, and show it only when both figures are known.
- Rejected: a margin in money. It needs tax basis per house (founder answers 2026-10-12), and pour % is the bar's own measure.
- Invariant: never a % from an unknown cost; "Not known" when either side is null.

**(d) List columns by kind.**
- Call: rows whose kind is not a drink show unit-of-measure columns (on hand in their uom, cost a uom), not btl/gl or "Add a bottle", and the band reads "INVENTORY".
- Rejected: separate pages per kind, because the founder asked for one list with all goods.
