# Request storm: 2026-11-12

**PR:** #1136 `fix/session-reads-are-not-sign-in-attempts` @1e6777245, DRAFT, base main. 9 files, 28.2K.

## Root cause
1. **"Thousands of requests in seconds" is not an API loop.**
   - It is the Vite dev server serving the unbundled module graph: about 3,550 browser requests per full load, of which 20-40 go to the gateway.
   - Client-side tour of all 21 sidebar routes on origin/main c459b0a12: every route made 1-47 gateway calls, then went quiet.
   - /login stayed idle for 20 s after a 429, with 0 requests.
   - The polish lane's ~34k buffered requests came from stale pane tabs left open by earlier walks.
2. **The 429 and the jump to /login are real.**
   - `RateLimitGuard.getRateLimitConfig` (apps/api-gateway/src/common/rate-limit/rate-limit.guard.ts) puts any path containing `/auth/` at 10 a minute per address and route, including `GET /auth/me`.
   - The web asks `/auth/me` per full load: 3 times in dev and 2 in prod. The asks come from authStore's module-level `loadUser`, plus AuthContext's `loadUser` (twice under StrictMode). An expired token makes 6.
   - On main: 3 dashboard loads plus 1 /settings load within a minute → 2 × 429 → landed on /login.
   - Every device in a house shares one public address, so this can happen in production.
3. **/login after a full load of /settings is not a separate bug.** Without a 429, /settings loads and stays. With a 429, main sends the person to /login, and #1092 fixes that half.

## Fix
- **Gateway:** `@RateLimit(SESSION_READ_RATE_LIMIT)` (100 a minute) on GET me, me/role, me/linked-providers and houses.
- **Web:** `lib/meAtBoot.ts` shares the boot read across both clients. It also handles a 401 with a single shared refresh hop.
