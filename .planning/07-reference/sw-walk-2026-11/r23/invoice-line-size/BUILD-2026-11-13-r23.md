# r23 invoice-line-size: D2, a line's own bottle size reaches the new good

## Audit (evidence)
- `CreateHouseItemDto` (#862, `apps/api-gateway/src/inventory/dto/house-item.dto.ts`) had no size field, so `HouseItemService.carry` inserted `bottle_size_ml` NULL.
- The inventory read `mapInventoryItem` (inventory.service.ts:87-95 at #862) did `row.bottle_size_ml ?? library ?? 750`. Every house good with no size therefore read 750 ml, with floor(750/pour) glasses.
- Readers of the size that can move money:
  - `PosMappingPanel.tsx:413` used `cand?.bottleMl ?? 750`, and its "Bottle 750ml" answer was saved as `sale_volume_ml`. **Fixed.**
  - recipe cost (#864 `recipe-cost.ts`) reads the raw column positive-only and says `size_not_known`. It is already honest; D2 now lets it cost a carried tonic.
  - pos-hub `inventoryVolumesFromRow` and procurement `resolveOrderShelfItem` read raw, positive-only. Already honest.
  - SQL `record_glass_pour` does `COALESCE(ri.bottle_size_ml, 750)`. **Not changed:** this is ADR 0297's labelled stand-in, mirrored in pos-hub.
- Display-only 750 fallbacks are left; they move no money:
  - `RowExpansion` Format;
  - `useInventoryPage` filter and sort;
  - `dashboard.service.ts:1207` total volume;
  - the `inventory_volume_details` view, which no app reads;
  - the simulator;
  - `volumeUtils.getEffectiveBottleSize`, which nothing calls;
  - wine library creation.

## PRs (all DRAFT)
- **#1296** `fix/house-good-keeps-its-size` <- `feat/inventory-house-items` (#862). 7 files, 15,378 chars.
  - Adds DTO `bottleSizeMl`. The service stores it for bottle (50-18000) or keg (1000-60000), refuses it on ml/g/each, and leaves NULL when absent.
  - The mapper gives a non-wine row with no own size `null` (no glasses, no oz). Wines keep library then 750.
  - PosMappingPanel shows "Bottle: size not known", disabled.
- **#1297** `fix/receipts-new-good-carries-line-size` <- `fix/receipts-line-adds-a-new-good` (#1268). 6 files, 13,368 chars.
  - `goodSize`: the line's `format_ml` is sent as `bottleSizeMl` for bottle/keg, and the form says "One bottle holds 200 ml, as the paper says."
  - When the size is unknown or out of bounds, the form says so and sends none.
  - `GoodBody` type is in `houseGoods.ts`.
- Merge order: #862, #1296, #1268, #1297. The ValidationPipe uses forbidNonWhitelisted, so #1297 without #1296 gets a 400 on a sized add.

## Calls (also in PR bodies)
- Fix the one mapper, not every caller. Wines keep ADR 0297's stand-in.
- Sizes apply only to bottle and keg (recipe-cost `CONTAINERS`).
- An out-of-bounds size is refused at the gateway. The web leaves it unknown and states the bounds.
- The panel disables the bottle answer. Rejected: a unit-only "bottle", which would queue every bottle sale of an unsized wine.
