### #1410: the Turkish i and accents (gap 14)

- **What it adds:**
  - **`name-fold.ts`.** `foldName` trims and collapses spaces, folds case, reads ı as i, and strips marks after NFD. Because the marks are stripped, ş reads as s, é as e, and the dot of İ goes too.
  - **`shelfSearchPattern`.** It turns a term into a PostgreSQL regex of letter classes (PostgREST `imatch` / `~*`), so "seker" finds "Şeker". Typed `%`, `_` and `.` are searched as characters.
- **Where it is used:** `matchShelf` and the shelf search.
- **The session's calls:**
  - Fold accents as well as ı/İ, because English keyboards cannot type the Turkish letters. Two goods that fold to one name already link neither.
  - A regex of letter classes, not a whole-shelf read on each keystroke, and not `ilike` with `_`, which would match any letter.
- **Tests:** recipes jest, 203 passed; `tsc` clean.
- **Mutants:** 10/10 killed (`mut/m1.txt`). F1 (`toLocaleLowerCase('tr')`) was equivalent once marks are stripped, so it was replaced by `toLowerCase()`.
- **Left:** the dish-name unique index still uses SQL `lower()`. Changing it needs a migration.

### #1414: the menu's price, gateway half (gap 2, slice 1)

- **The route:** `GET /recipes/:rid/menu-prices` returns `{ amountsWithheld, currentMenus, dishes: [{dishId, menu}], drinks: [{cocktailId, menu}] }`.
- **The answer for each row (`menu`):**
  - `{found:"one", prices, agrees}`: `prices` are the distinct bottle and glass prices, rounded to cents. `agrees` is null when either side has no price.
  - `{found:"several", lines}`: lines of that name that disagree.
  - `{found:"none"}`.
- **The rule (`menu-price-match.ts`):**
  - Names are compared under `foldName`.
  - A dish prefers kitchen lines (`isKitchenLine`) and a drink prefers the others. Each falls back to every line when its own side has none.
  - A drink is tried by its shown name first, then by its own name.
  - Lines with the same prices count as one answer.
- **Reads and refusals:**
  - Current menus only (`readCurrentMenuLines`), keyset-paged past 1,000 rows.
  - Staff read nothing.
  - A failed read is a 503 with a sentence.
- **The session's calls:**
  - Match in the gateway, not in the web as the brief had it, so there is one fold, not a copy in a second language.
  - Show only. Rejected: storing a `dish_id` on `menu_items`, which is per upload; and reading `menu_price_current`, which prices goods.
  - The own-side fallback exists because main's `KITCHEN_HINTS` misses "Mains" (#1390 widens it).
- **Tests:** 12 new specs, 216 passed in all; `check_read_columns_exist` PASS.
- **Mutants:** 12/12 killed (`mut/m2.txt`). P12, a blank-name guard, was equivalent and removed.

- **Gap 7, unit bridges. This is the next hardest gap; a design for it follows.**
  - **Invariant:** a line is priced or counted through a bridge only when the house has stated that bridge for that very good. Never a default weight: no "egg = 50 g" table.
  - **Schema:** add `restaurant_inventory.piece_grams numeric(10,3) null check (piece_grams > 0)` and `ml_grams numeric(8,4) null check (ml_grams > 0)`, the density.
  - **`recipe-cost.ts` `baseUnitCost`:**
    - `each_milli` against a g, kg or mg good is priced as `(unitCost per g × piece_grams) / 1000`;
    - `ml10` against a weight good uses `ml_grams / 10` g per base unit;
    - `mg` against a volume good uses `1 / ml_grams`;
    - a missing bridge returns a new `why: "needs_piece_weight"` or `why: "needs_density"`, never `unit_mismatch`.
  - **`recipe-nutrition.ts`:** the same bridges.
  - **`pos-hub/recipe-draw.ts` `route()`:** the same bridges, with a parity spec, and the movement stamps the `piece_grams` it used, so a later edit never rewrites a past draw.
  - **UI:** the inventory drawer gets a field "One weighs ___ g" for food goods. A sheet line marked "needs the weight of one" offers the same box inline to owner and manager, and the existing manager-gated house-item PATCH writes it.
  - **Cases that break it:** a value of 0 or below (refused by the CHECK); the good's uom changing from g to kg (the factor is per gram, so it is unchanged); another house's good (the PATCH is house-scoped); a sale between two edits (the stamp).
  - **Rejected:**
    - a weight per recipe line, repeated in every recipe and drifting apart;
    - converting at entry time, which loses the bridge when the good's weight is corrected;
    - a global default table, which is a guess.
- **Gap 8, add a good from the sheet when nothing matches.** A Sonnet-sized job.
