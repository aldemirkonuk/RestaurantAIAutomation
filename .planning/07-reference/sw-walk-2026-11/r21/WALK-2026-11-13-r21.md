## Open defects, not fixed

- **D1 (medium-high): a menu line added by hand or imported duplicates a good the house already carries.** Walk evidence (local DB): hand "Add to menu" of "Local Check Cabernet 2020" made library row 0d339511 (no vintage, no producer) and a second inventory row beside the seeded one (master c1, "Local Check Cabernet" 2020). The CSV line "House London Dry Gin, Spirits" made library row 92bfdc03 and a kind=wine inventory twin of the house_declared spirit. Cause: `menus.service.ts` resolveAndPersistItems (~2399) sends every drink line to the master_wine_library resolver. The inventory seed (~2673) finds house rows only `.in("master_wine_id", …)`, never by the house's own display_name or kind. `menu_items.inventory_item_id` exists, so a house-row link needs no migration.
  - **Brief (Sonnet-ready):** in `resolveAndPersistItems`, before the library resolver, read this restaurant's live `restaurant_inventory` rows (id, display_name, wine_name, kind, master_wine_id; chunk past 1000 rows). Match each drink line's name (trimmed, case- and diacritic-folded, internal spaces collapsed) against display_name and wine_name.
    - On exactly one hit, link `menu_items.inventory_item_id` to that row and use its master_wine_id (which may be null for a house_declared spirit). Do not send the line to the resolver, and do not seed a new inventory row.
    - On zero hits, keep today's path.
    - On two or more hits, keep today's path and add a read warning naming the candidates.
    - Pricing for a matched house row follows the existing menu-price sync (ADR 0193), keyed on the inventory row.
    - Tests: a hand add of an exact house name makes no library row and no inventory row; a spirit line matching a house_declared spirit links it, not a wine twin; a name matching two rows warns; a tenant's rows are never read for another restaurant_id.
    - Owner: the newest open PR on menus.service.ts (the r21 menu chain). New stacked PR, ≤15 files, ≤30K.
- D2 (medium): a line's `format_ml` (Tonik 200 ml) does not reach the new good. `CreateHouseItemDto` has no size field, so the good's bottle_size_ml is NULL, and anything that costs it per ml falls back to the read path's 750. Gateway DTO + web body change, owner #1268. Noted on #1268.
- D3 (low): the senders block in Mail setup (gateway house-sender.service.ts:617) tells an owner "An owner or a manager can turn it on." The sentence ignores the role.
- D4 (low): /menu's hand-added unpriced spirit says "the house had no price for this wine either".
- D5 (low): mixed number locales on the document sheet ("₺2.200,00" vs "₺300.00"). The drawer shows "TRY" where other pages show "₺". "COST A SERVE" reads ambiguously. Cocktails says "2 on the menu" and also "No menu line… names a cocktail".
- D6 (low, a11y): the /get-started typed-line inputs and the country combobox have no labels or roles (only the price box has an aria-label). The typed-line price is `type=number` + parseFloat, so "24,50" was not exercised (a native setter cannot reproduce browser typing into a number box).
