### #1650: three indexes (migration `20271119103700`)

The indexes:

- `wine_consumption_log (restaurant_id, id, created_at)`
- `wine_consumption_log (restaurant_id, created_at)`
- `pos_checks (restaurant_id, id, opened_at) WHERE voided = false`

The session's call:

- The key leads with the house, then `id`, so a page is a range of the house's ids in the order `readWholeWindow` pages in.
- Rejected:
  - `(restaurant_id, created_at)` alone. Measured, the page still walked the primary key.
  - Re-keying the cursor to the window column, which would change every reader and the ADR 0292 stability proof.
  - Counting only on the first and last page, for the same reason.
- The check index is partial, because without the predicate the count stayed a 6,960-buffer bitmap scan.
- No orders index: it only moved 1,294 buffers to 879.

Evidence, from a throwaway database on fixlane-pg cloned from `main_tpl` at c459b0a12: 20 houses at 131 consumption lines, 58 checks and 6 orders a day for a year. Buffers per statement, for 20 houses and then 1 house:

| Statement | 20 houses | 1 house |

| Consumption 90-day page | 81,850 -> 1,033 | 4,440 -> 1,033 |
| Consumption count | 16,777 -> 175 | 16,488 -> 175 |
| First line | 16,780 -> 4 | 16,491 -> 4 |
| Checks 365-day page | 19,143 -> 1,010 | 1,076 -> 1,010 |
| Checks count | 6,960 -> 80 | 6,941 -> 80 |

Whole-chain milliseconds were noisy (load average 50 to 200):

- checks 365 d: 571–1,384 -> 203–334 ms

### #1675: the till's per-wine breakdown is opt-in

The session's call: `include=consumption` opts in. Without it, the `consumption` key is absent from the JSON. With it, the behaviour is unchanged: `[]` with no POS, `null` with no zone.

No reader draws the breakdown. `git grep -n "pos-revenue"` finds the /reports till select, the /recommendations hook (`dailySeries` only) and the export (`getPosRevenueWindow` directly), and nothing on mobile or in Python. `getPosConsumptionBreakdown` has no other caller.

Rejected:

- `Promise.all` alongside the checks (the audit's shape). It still reads 48 pages with exact counts for a discarded field.
- Deleting the breakdown: a larger change to the contract.

Before and after:

- Breakdown calls per default till load: 1 -> 0.
- A 365-day load at the live house's rate: about 22 check pages plus 48 consumption pages -> about 22.

- The removed consumption chain measured 4,155–4,877 ms (no indexes) and 73.5–113 ms (with #1650's) on the bench.
