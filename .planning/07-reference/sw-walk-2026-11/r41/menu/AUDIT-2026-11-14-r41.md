**First paint of /menu: four reads, all fired in parallel (serial depth 1).** None waits on another.

| Request | Code | Gateway serial DB trips |
|---|---|---|
| `GET /menus/:rid` | `MenuNext.tsx:117-120` | 1 actives + ceil(lines/1000) pages + ceil(linked/150) house-price chunks, run one after another (`menus.service.ts:1398-1420`, `:1453-1466`). For a 300-line menu with every line linked: 1+1+2 = 4. |
| `GET /settings/currency` | `MenuNext.tsx:101-110` and `useHouseCurrencyCode` | 1 request, shared by one key |

| `GET /menu-versions` | `MenuVersions.tsx:413` | pages + names |

**Plan (`GET /menu-versions/:id/plan`, `menus.service.ts:1753-1788`).** At least 8 serial trips for a draft menu, and none of them depends on the one before:

1. Version row
2. Lines
3. Every inventory row of the house, removed ones included, with a `master_wine_library(vintage)` join (`:1810-1826`)
4. Open locks
5. Open price versions (`:1836-1858`)
6. Active menus
7. Lines of the menu being replaced (`:1867-1880`)
8. Names

**Make current (`:2148-2302`).** The plan is recomputed in full: 3 trips, then computePlan's 6 or more. Then come the RPC and `addToInventory`, whose wine-id and good-id chunk loops run one after another (`:2849-2877`, `:2992`). That is about 15 or more serial trips for a 300-line menu.

**Indexes.** Every filter column the menu reads use has an index:

- `menu_items(menu_id)`, `(restaurant_id)`, `(restaurant_id, status)` (baseline :9647-9661)
- `restaurant_menus(restaurant_id, status)` (:10963)
- `restaurant_inventory(restaurant_id)` (:10865)
- `menu_price_versions` lookup, restaurant and one-open (20260805123951:70-79)
- `house_price_locks_house_open` (20260922230800:98)

No index is missing.

**Re-renders.** Typing stays local:

- A price box's draft lives in MenuRow (`MenuNext.tsx:349`).
- The Add form keeps its own state (`:167-170`).

No per-keystroke render of the table was found. A plan tick re-sorts and re-renders the whole plan (`MenuPlan.tsx` `orderedRows`). That is cheap at menu sizes, and it is not ranked.

## Ranked gaps NOT fixed by any open PR

### R1 (high, goal: "menu upload … typed"). A typed menu exists only in owner onboarding. /menu cannot start a menu by typing
- The typed read `MenuManualEntry` (`importMenu('manual')`) is mounted only in `pages/GetStarted.tsx:381`. /menu's read box takes a file only: photo, PDF, CSV or xlsx (`MenuVersions.tsx:199-210`).
- /menu's "Add to menu" needs a current menu:
  - The code refuses: `throw new Error('No active menu to add to')` (`MenuNext.tsx:139`).
  - The page says so: "Add to menu has nothing to add to until a menu is current" (`:658`).
- Open #1535 now sends every **manager** from /get-started to /menu, and a manager is never shown owner onboarding. So a manager has no way to type a menu, and neither has an owner whose onboarding is done.
- **Open PR:** none. No open diff mounts MenuManualEntry, or `importMenu('manual'`, outside GetStarted.

### R2 (medium-high, speed). Making a menu current reads the plan again, for a menu that is already current
- `MenuPlan` invalidates `['menu']` in `choose.onSuccess` while the plan query is still mounted (`MenuPlan.tsx:327-330`). Its parent then invalidates `['menu']` again:
  - Menus kept: `MenuVersions.tsx:486-488`, through `refresh()`.
  - The read box: `MenuVersions.tsx:323-328`, which calls `invalidateQueries(['menu'])` and then `onRead()`, two more.
- The client sends no abort signal (`services/api/menus.ts:535-538`), so a cancelled refetch still reaches the gateway.
- **Probe P3** used a parent that closes the plan on done: **2 plan reads for 1 make-current.** The read-box path invalidates two more times.
- Each extra plan read costs at least 8 serial DB trips, a full inventory read among them. The result is thrown away.
- **Open PR:** none.

### R3 (medium, speed). Plan, make-current and the menu read wait on independent reads one at a time
- `planFor` (`menus.service.ts:1753-1756`) and `makeCurrent` (`:2185-2187`) await the version row, the lines and `isOnlyCurrent` in turn.
- `computePlan` awaits, one after another, the inventory pages (`:1810-1826`), the locks (`:1830`), the open price versions (`:1836-1858`), the actives and the replaced lines (`:1867-1880`). None of them needs another's answer.
- `housePricesOf` (`:1453-1466`) and the `addToInventory` chunk loops (`:2849-2877`, `:2992-3005`) also read chunk after chunk.
- `computePlan` reads every inventory row the house ever had, removed ones included, with a library join (`:1813-1815`). Once foods are goods, this grows with the larder, not with the menu.
- **Open PR:** none. No menu-area diff adds `Promise.all` to these paths. The only `Promise.all` hits are setup and onboarding (#1413, #1532, #1593, #1612) and a test in #1062.

### R4 (medium, goal: price changes "smoothly"). /menu has no way to find a line
- Every line is drawn in two flat tables, sorted by section and then name (`menus.service.ts:1558-1561`, `MenuNext.tsx:561-562`, `:715`). There is no search or filter box.
- To change one price on a 300-line list, the owner scrolls through the whole menu.
- **Open PR:** none. No diff adds a find box.

### R5 (medium-low, speed). Coming back to the tab re-reads all of /menu, and an open plan, every time
- The app defaults are `staleTime: 5_000`, `refetchOnWindowFocus: true` and `refetchOnMount: 'always'` (`App.tsx:160-162`). /menu overrides none of them.
- The Source link of a kept menu opens the file in a new tab (`MenuVersions.tsx:354-355`). Coming back from it re-reads the menu, the versions and the locks. If the plan is open, the whole plan is computed again, at 8 or more trips.
- This is the very flow of checking a plan against its file.
- **Open PR:** none.

### R6 (medium-low, fit once chain B merges). Two pollers on one background read, and one of them re-reads the whole list
- #1063 `waitForRead` polls `GET …/read-status` every 1.5 s, then every 4 s, for up to 20 min (`READ_WAIT_MS`).
- At the same time, #1064 sets `refetchInterval: 5000` on the whole Menus kept list while any version is "reading". Each list read also runs #1061's `sweepStaleReads`, then the paged versions, then the names.
- A read left stuck stays "reading" until the 30-min sweep (`READ_STALE_MS`, #1061). That is up to about 360 list reads per open tab.
- **Open PR:** none changes it. It shows only once chain B is merged.

### R7 (medium-low, money; fit once #761 merges). Two price readers for the same box, and the CSV one drops a minus sign
- The train's Change price uses `parseMenuPrice` (`menus.service.ts:476-510`). #761 rewrites the same `reviewMenuItem` hunk to `readMenuPrice` (#761 `menus.service.ts @@ -821`), and #761's CSV path uses it for cells.
- **Probe** (`data/probe-price-readers.txt`):

| Input | readMenuPrice | parseMenuPrice |
|---|---|---|
| `-45` | 45 | refused |
| `CHF 12` | 12 | refused |
| `ca. 45` | 45 | refused |
| `45-` | 45 | refused |
| `0,250` | 0.25 | refused |

- In a CSV, a discount row "İndirim;-10" becomes a line priced 10 and is carried as a good.
- r21 and r33 named the conflict ("whoever lands second must choose") and left it undecided.
- There are also two money-mark tables: `menu-money.ts` (#1543) and `parsers/price-mark.ts` (#1617). They agree today. r40 kept them apart on purpose, so they can drift.
- **Open PR:** none decides it.

### R8 (low-medium, fit once chain B and #1607 merge). Price history prints UTC days, and is not refreshed by a price change on the same page
- #1607 `PriceHistory` writes `v.from.slice(0, 10)` and `v.to.slice(0, 10)` (#1607 `PriceHistory.tsx`, `versionWords`), which are UTC dates.
- Chain B #1257 adds `menu-clock.ts` `houseDay(iso, zone)`, and Menus kept says its days in the house's zone.
- In Antalya (UTC+3), a change at 01:30 on 2 Nov reads "since 2026-11-01".
- `savePrices` invalidates only `['menu','active',…]` (`MenuNext.tsx:557-559`), so an open history stays on the old price after a Change price.
- **Open PR:** none.

### R9 (low-medium, cold load). Three status lines and no reserved space, so the page jumps when the menu arrives
- What shows while reading:
  - "Reading the menu…" (`MenuNext.tsx:646-649`)
  - "Reading the locked prices…" (`LockedPrices.tsx:249-254`)
  - The read form, then "Reading the menus this house has kept…" (`MenuVersions.tsx:432-435`)
- When the current menu answers, its tables land above Locked prices and the read box and push them down. A 200-line menu pushes them by the whole table.
- `HousePageSkeleton` (`components/mudavym/HousePageLoader.tsx:39`) exists and is not used here.
- **Open PR:** none.

### R10 (low, absence read as a fact). Before the money is read, every price says "(currency not recorded)"
- `useHouseCurrency` returns `null` while the read is pending (`MenuNext.tsx:101-110`). `formatMoney(null)` then prints "… (currency not recorded)" (`lib/currency.ts:361-366`).
- **Probe P2:** the row reads "12.00 (currency not recorded)48.50 (currency not recorded)" until `/settings/currency` answers. "Not recorded" is said while the read is merely still on its way.
- **Open PR:** none.

### R11 (low, fit). Two hooks for the same house-money read
- MenuNext has its own `useHouseCurrency` (`MenuNext.tsx:101-110`), without `enabled`. `hooks/queries/useHouseCurrencyCode.ts` does the same read with the same key, and is used by MenuVersions, ReadMenuForm and MenuPlan.
- **Open PR:** none.

### R12 (low, words, fit once merged). Five verbs for taking things away on one page
- "Discard" (current menu line)
- "Leave this line out" (#1584, a draft's line)
- "set aside" (#1415/#1530, an archived menu)
- "Put away" (#1640, a kept menu)
- "take off sale" (#1497, the house price)

r40 chose "put away" to avoid a clash with "set aside". The page still asks a manager to learn five words.
- **Open PR:** none.

## Tried and killed (step 4)
- **A stale price draft re-sends an old price.** MenuRow keeps its draft from mount (`MenuNext.tsx:349`), so the guess was that a glass-only change would re-send a stale bottle price.
  - Probe P1: after a refetch to bottle 60, the box showed "60,00", and only `by_glass_price` was sent.
  - Probe P2: after a late currency read, the box showed "48,50", and only the glass was sent.
  - Reason: Change price resets the draft on open (`:490`). **Killed.**
- **Cross-house read on `GET /menus/:restaurantId`.** The controller has only `JwtAuthGuard` (`menus.controller.ts:37,46-54`), but the global TenantGuard runs `assertTenantMatch` on path params (`common/tenant/tenant.guard.ts:80`). **Killed.**
- **N+1 on import.** Library resolve is one RPC (`wine-submissions.service.ts:792`). Inserts and the write-back are batched, and per-row only on fallback (`menus.service.ts:2914`, `:3101`). **Killed.**
- **Missing indexes.** All present (see Measurements). **Killed.**
