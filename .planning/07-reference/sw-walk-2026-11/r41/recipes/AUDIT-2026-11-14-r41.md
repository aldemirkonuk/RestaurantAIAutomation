## Gaps NOT fixed by any open PR (ranked by impact on the goal)

### 1. /cocktails loads the whole cellar before and beside the drinks — a 500-row `select *` wine library, the full inventory polled every 60 s, providers
- `/cocktails` mounts `CellarNext` (App.tsx:431), which calls `useCellarNextData()` unconditionally (CellarNext.tsx:85).
- That hook reads `GET /wines?limit=500&offset=0` with no `enabled` (useCellarNextData.ts:1327-1343); the gateway answers `master_wine_library.select("*")` (wines.service.ts:492), a ~90-column table (baseline DDL).
- It also mounts `useInventory()` (useCellarNextData.ts:1344): the whole house inventory with its lot rollup, `refetchInterval: 60_000` (useInventoryQueries.ts:70), and `useProviders` (:1345).
- None of it is used for cocktails: `CatalogueRegister` returns the cocktail branch with only `data.registers` (CatalogueRegister.tsx:300-305).
- So a bartender opening /cocktails pays for the wine catalogue and the inventory, and the open tab re-reads the inventory every minute.
- **Gets worse on merge:** #1005, #1017 and #1072 add `useLowStockItems()` to the same hook (all-add grep `useCellarNextData.ts`), so one more house-wide read on /cocktails.
- **Open PR fixes it?** No. No open PR adds an `enabled`/category gate to `useCellarNextData.ts` (grep of added lines for `enabled|category` in that file: none).

### 2. /dishes shows no dish name until every line of every dish is priced
- `useDishes` is the page's only list read (DishesPage.tsx:280); the page shows "Reading the dishes…" until it answers (:327-328).
- The gateway's `listDishes` awaits `figures(..., {allergens: true})` before returning names (#1609 dishes.service.ts:149-161).
- Its serial depth: dish pages → pointer waves → version+line waves → pricing (5 cost views per 100 goods) with allergens beside it (#1609 :189-290). 120 dishes is 1 + 2 + 2 + 1 = 6 serial DB round trips; 300 dishes is ~10.
- /cocktails does the opposite: names come from their own cheap read and costs fill in later (CocktailRegister.tsx:160, 171). The two lists load differently.
- **Open PR fixes it?** No. The only PRs touching `listDishes` are the train itself (#1251…#1621); none splits names from figures.

### 3. On /dishes, one failed cost view takes away the names and the allergens too; /cocktails keeps them

- On /cocktails, the same failure blanks only the cost cells and says `DRINK_COSTS_UNREAD` (CocktailRegister.tsx:385-389).
- **Open PR fixes it?** No.

### 5. Every focus and every mount re-reads the house-wide figures; the recipe hooks' `staleTime` is dead
- The app defaults are `staleTime: 5_000`, `refetchOnWindowFocus: true`, `refetchOnMount: 'always'` (App.tsx:158-166). 'always' ignores staleTime.
- So the 5-minute `staleTime` on `useHouseMoney` (useHouseMoney.ts:50), `useHousePercent` (useHousePercent.ts:27) and `useSayGrams` (WeighBox.tsx:40) never applies: each sheet open re-reads the house currency.
- `useDishes`, `useDrinkFigures` and `useMenuPrices` (useRecipe.ts:41-104) set none. Alt-tabbing back to /cocktails after 5 s refetches about 10 reads, three of them house-wide pricing, plus the full inventory and the 500 wines (gap 1).
- Re-opening a row re-runs `useRecipe` (3 serial gateway hops, ~10 DB reads).
- **Precedent:** #1240 (useUserPreferences.ts) and #598/#671 (useOrderBook.ts) already override with `refetchOnMount: true`, and #1240's comment names the cause.
- **Open PR fixes it?** No recipe hook does this (added-line grep `refetchOnMount`: only #1240, #598, #671).

## Decisions (the session's call, for whoever builds)
1. **Gap 1: gate the cellar reads by route.**
   - Pass `category` into `useCellarNextData(scope)` and set `enabled: scope !== 'cocktails'` on wines, inventory, providers and low-stock.
   - *Rejected:* a separate /cocktails page without CellarNext. It duplicates the spine, the name rule and the footer.
2. **Gap 2 (and 3): split /dishes like /cocktails.**
   - `GET /recipes/:rid/dishes` returns names and prices (one paged read).
   - A new `GET /recipes/:rid/dishes/figures` returns the figures. The web joins them as `useDrinkFigures` does.
   - A failed figures read then blanks only the cost cells.
   - *Rejected:* skeleton rows over the same single read. They still wait for the pricing and still 503 the names.
3. **Gap 5: per-hook `refetchOnMount: true`, the #1240 pattern.**
   - Use `staleTime: 60_000` on the list figures, and keep the 5-minute value on currency.
   - *Rejected:* changing App.tsx's default. Every lane would be affected, beyond what this audit can verify.
4. **Gap 7: scroll the leaf into view on any open.** Key the existing effect on `openId`, not only on `linkedRow`.
   - *Rejected:* rendering the leaf inside the row as /dishes does. That inherits r34 F11's phone overflow.
