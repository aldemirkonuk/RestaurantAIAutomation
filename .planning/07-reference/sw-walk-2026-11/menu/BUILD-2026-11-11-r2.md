## Fix round (2026-11-11)

Two NITs on #1100. I confirmed both in `apps/api-gateway/src/menus/menus.service.ts` at 7f743fc3e (lines 1518-1529 and 1530-1546) and fixed both in dffbe0e73 on `feat/menu-plan-says-what-is-not-on-this-file`. The fix was then merged up with merge commits: e348592f2 into #1101 and 13bab2b85 into #1102. Nothing was force-pushed.

- **A name match hid a vintage change.** Before, a replaced line counted as present whenever any line on the new file had the same folded name.
  - Now a linked replaced line counts as present when either (a) the file carries its wine, or (b) an *unlinked* line on the file has the same name, since that line may be the same wine. An unlinked replaced line still matches any line with the same name.
  - So "Barolo" 2015 (mw-2) replaced by "Barolo" 2018 (another wine) is now listed.
  - The session's call. I rejected "compare ids only when both sides are linked, otherwise names" in the strict per-pair form. It needs a pairwise check for every file line. The two set lookups give the same answer, with one exception: a file that has the same name both linked to another wine and unlinked still hides the line. That case is ambiguous, so it is left out of the list.
- **A deleted or inactive row read as sold.** Each entry now carries `active`, computed with the rule that `PlanLine.house.active` and `DormantLock.active` already use: false when `deleted_at` is set or `is_active` is false, null when there is no row.
  - The page now says "the house no longer sells it; its row keeps bottle X".
  - The session's call. I rejected the finding's other option, treating such a row as `inventoryId: null`. The page would then say "nothing is kept", which is false, because the row and its prices stand and nothing is written (L12).
  - `active` is not part of the L13 fingerprint. It is display only, as `DormantLock.active` is.
  - `UNIQUE (restaurant_id, master_wine_id)` (baseline, line 7672) means a deleted row never shadows an active row for the same wine.
