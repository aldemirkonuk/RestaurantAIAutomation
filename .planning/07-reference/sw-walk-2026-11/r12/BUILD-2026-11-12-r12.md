**Findings:**
1. **CRITICAL, fixed in #1210:** the /get-started reload loop. Before the fix, a new owner could not get through setup at all.
2. **Verify mail does not send locally.** There are no mail credentials on the local stack; this is expected. The token was read from `email_verifications` locally.
3. **The "Type a few lines" menu entry is wine only** ("Wine Name *", "Import wines"). A food-led house has no path here.
4. **First-proof wording:** "THE FIRST PROOF", "READ/SET/PENCILLED" and "Needs a place" are jargon, and nothing shows that a line can be clicked to fix it.
5. **Dead-end ambiguity:** onboarding says "The first proof is set", but the dashboard then says the menu is not current, and it takes 3 more clicks on /menu. #1053 (feat/menu-first-menu-becomes-current) is already working on this; it was not in the integration.
6. **The first dashboard stacks four interruptions:**
   - The data-terms modal, which names OpenAI/Upstash/Railway/Vercel/CloudAMQP and "Jev (TypeSafe)".
   - The theme modal.
   - The setup banner.
   - The tour tip.
7. **On /menu, "Make current"** opens its plan below the fold without scrolling to it, so the click looks like it did nothing.
8. **Menu dates are shown in UTC** ("menu read 2026-11-13") while the house's local date is Nov 12 (America/Detroit).
9. **Plan and result disagree:** the plan said "will add 2 prices for wines new to the house", and the result said "1 price set from this menu".
10. **Status "flagged"** is not explained anywhere.
11. **Console:** the 403s were all from the loop. After #1210, every dashboard API call returned 200. WebSocket errors are local only.
