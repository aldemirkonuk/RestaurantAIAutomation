- **(b)** Probed with the real controllers over HTTP against an empty fake DB (evidence is in the #1331 body). `ai-pause`, `dismiss-deal` and `discard-draft` gave 500 for any unknown id. `deliver`, `confirm-deal`, `confirm-deal-seal-challenge`, `conversations` and `draft` gave 500 for a non-uuid. `attachments`, `conversations`, `deal-proposal`, `draft`, `cancel-scheduled-send` and `generate-ai-reply` answered 200/201 with an empty body for an order that does not exist. The 404s that did exist used inconsistent bodies.
- **(c)** ADR 0254 rule 4 (moving an approved order on needs an owner, a manager or someone given the right; "delivered" only from the door) was never built. #577 built rules 1-3 and #538 covers ADR 0244 D1/D2. A received or closed order could still be edited through PATCH. No page calls PATCH `orders/:id` today (`updateOrder` in `apps/web/src/services/api/orders.ts` has no importer), so the rules close the route itself.
- **(a)** After #1283, a removed vendor took no new order, but removal touched nothing else:
  - its order recurrences stayed `active` and every 08:15 run logged a failure;
  - its legacy schedules stayed `active` and every 08:00 run logged a failure;
  - a legacy schedule could be created or resumed for it;
  - a PENDING order for it could be approved;
  - a staged AI reply to it went out on its timer.
  - **No web page removes a vendor:** `/vendors` (`ProvidersNext.tsx`) has no remove control, `useDeleteProvider` has no caller, and only `lib/sync-manager.ts:109` calls DELETE.

## The session's calls (each is recorded in its PR body with the rejected alternatives)

1. **(a)** Pause, not end, on removal. Keep and count open orders, not cancel (cancel is sealed, needs a reason, and goods may be en route). Settle after the removal and never throw.
2. **(a)** "Refuse new sends" means no approval and no automatic send. A reply a person writes about a placed order (manual reply, approve a draft, confirm a deal) stays open. The check sits before the claim, not in `sendProviderEmail`, because `approveDraft` would park the refusal as SEND_UNCONFIRMED.
3. **(a)** A legacy save checks only a resume or a running schedule naming a vendor. Pause and other edits stay open, and ADR 0249's "reads neither table" still holds.
4. **(a)** `setRecurrence` and resume are not refused here (#558 owns them). The generator pauses such a series at its first run instead.
5. **(b)** One interceptor, not 36 handler edits. GET runs the check in parallel so reads cost no extra latency. A write is checked before the handler runs. If the check itself fails, the request passes through, because the handler's own fence is still there.
6. **(c)** "Given the right" is read as a live `vendor_send` grant, the only right an owner can give today. Closed means goods arrived or terminal. The first B (all edits manager-only) was dropped because it duplicated #538 and #577 and contradicted ADR 0244 D2.
