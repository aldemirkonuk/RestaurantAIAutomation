# r25 calendar-followups — BUILD 2026-11-13

Lane: from r22 /calendar, these were fixed: B5 multi-day entries, B4 reminder re-arm on edit, and the end-before-start check on the update path. App-wide: web forms print the gateway's sentence, never "Request failed with status code 400".

## Audit (what was wrong, file:line at the bases)

- **B5, gateway.** `calendar.service.ts listEvents` bounded rows by `start_date >= window start` only. An entry that began before the window but runs into it (a 28 Dec to 3 Jan closure viewed in January) was never returned.
- **B5, web.** `useCalendarNextData` byDay put each entry on its start day only. The EventSheet disabled "Ends on" for all-day entries and dropped the end, and a cleared end was never sent.
- **Update path.** `updateEvent` did not compare the new end with the stored start, or the new start with the stored end. Clearing the end wrote `end_date` only, and the `sync_calendar_event_date_columns` BEFORE trigger then copied `event_date_end` back. The controller turned the worded 400 into a 500. The DTO refused `null`.
- **B4.** `calendar_reminder_dispatches` was unique on (event, user). After a move, the new instant's claim hit the old row, so a moved entry was never reminded again. `reminder_sent` stayed true, and the roll-up read every instant's rows.
- **App-wide.** Axios puts "Request failed with status code N" on `.message`, and most surfaces print `.message`. `getErrorMessage` returned axios text whenever the body was not a plain string.

## Calls (the session's, with the rejected alternatives in each PR body)

- **Overlap is the default list bound for every reader.** I rejected an opt-in flag: today, upcoming and house-day also need running entries.
- **Re-arm is done by a DB trigger, with due_at in the unique key.** Rejected alternatives:
  - service-side clearing on PATCH (misses agent writes, races the job);
  - deleting the ledger rows (loses history and allows a double send);
  - an updated_at guard (any title edit would re-arm).
- **Multi-day entries are drawn as per-day copies.** I rejected a spanning bar, which the grid layout does not support. Continuations are not draggable.
- **The end-before-start refusal is in the sheet.** I rejected a `min` attribute, because native validation silently blocked the submit.
- **App-wide: fix the one shared interceptor.** I rejected per-form edits. The fix wraps the existing handler; I rejected a second `use()`, which broke the handler-capture test. A worded 5xx is kept. The plain 5xx, timeout and no-answer sentences are neutral (a write may have landed). This reverses one older test that pinned the axios 502 text.
