## Findings (not fixed here; no open PR covers them — checked against all 920 open PRs by title/branch)

- **R-F9 — staff lose `daysLeft` with the reading.** `withheldProgress` nulls `daysLeft` though the deadline (shown) is not a money or till reading. Low impact (the card prints the date). Brief: keep `daysLeft` in the withheld entry; one spec line; mutate by nulling it again.
- **R-F10 — #1513's "too few weekdays" sentence is unreachable, and a house that recorded one weekday is told six "share the lowest mean".** `getSeasonality` passes `weekday.profiles.length`, but `houseDaily` zero-fills every day, so profiles is always 7 over 90 days. Brief: count weekdays with at least one counted line (`consumption.filter(c => c.qty != null)` → distinct house weekdays) and, when fewer than two, pass that count to `extremesBasis` AND null `bestDay`/`worstDay` with `tie: true` so the figure and the working agree; spec: Saturday-only log → both null + EXTREMES_TOO_FEW; mutate the count source and the null-out. Owner: #1513.
- **M-F2 — a filed letter carries no mark that a person vouched for it.** The thread shows "arrived at Mudavym's mailbox or your Mudavym address" only; `email_headers.filed_from_held` (who, when, why held) is not shown. With "Bank details changed" as the stock example this matters. Brief (#1521 or a follow-up): in the thread's letter footer, when `email_headers.filed_from_held` is present, say "Held because the sender could not be confirmed; filed under ‹vendor› by ‹name›, ‹when›."; gateway must pass the field through the thread read; spec + one web test; mutate the presence check.
- **M-F3 — focus is dropped on the file-under act.** Opening the confirm and pressing Cancel both leave `document.activeElement` = body; two held rows from one vendor give two buttons with the same name "It is from Anatolia Wines: file it there…". Brief (#1521): focus the "File it under ‹vendor›" button on open, return focus to the opener on Cancel; give the opener an aria-label naming the subject ("File ‹subject› under ‹vendor›…"); web test for both; mutate each.
