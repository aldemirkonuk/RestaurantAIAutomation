## The session's calls

- **G1.** Stored data has no null pack: a pack size of 1 on case, pack or split_case means "never stated", because the column is NOT NULL DEFAULT 1. The pack is taken from the paper if it states one (2 or more), otherwise from the door's answer. If neither is known, the count is refused (422) with a sentence and nothing is written. Fractional bottle counts are refused too, which covers G13.
  - Rejected: a guessed default of 12 or 6, which silently mis-stocks; treating 1 as a real pack, which is the bug.
- **G2.** One ORDER BY change inside `apply_stock_movement`: a negative movement that names a delivery draws that delivery's own lots first, then the oldest. Every other movement keeps the FIFO it had.
  - Rejected: a separate reverse function (a second stock primitive); a new argument (an overload and PostgREST ambiguity); deleting lots (R6 keeps them at 0).
  - On the gateway, the delivery stays REJECTED. The answer carries `stockReturn`, a failure notifies the house once (`delivery_stock_not_returned`), and `POST :id/return-stock` retries for REJECTED or CANCELLED deliveries.
  - Rejected: rolling the state back, or reversing before the state update.
- **G3.** `holdsHouseMoney` (owner, manager, admin) gates propose, counter, accept, accept-as-billed, agree, verify and return-stock with a 403 sentence. Door work stays open to everyone. The proposal thread returns the two money keys as null to non-holders, with `moneyWithheld: true`.
  - Rejected: `@Roles`, which is an exact match and refuses admin; hiding the whole thread from staff.
- **G6.** The lot cost is (bill + charges − credit claimed) / accepted, so cost × accepted + credit = bill + charges. A credit the vendor later refuses is a write-off, not a re-cost.
  - Rejected: keeping the full bill and dropping the credit; re-costing at settlement; spreading only the charges.
