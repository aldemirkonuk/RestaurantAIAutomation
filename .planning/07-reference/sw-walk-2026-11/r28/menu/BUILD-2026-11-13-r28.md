## The session's calls (founder delegated forks, 2026-11-07 /goal)

- **G1, batch versus parallel versus job.**
  - Chosen: a DB-side batch through the one lock-holding writer, with a savepoint per row.
  - Rejected: parallel gateway calls, which still take about 20 s for 485 lines and use 8 pooler connections.
  - Rejected for now: a background job with polling. It needs a job table and a polling UI. It is the next slice if a menu runs to thousands of lines.
- **G1, resuming a cut-off carry.**
  - Chosen: choosing the current menu again re-carries, dated by `made_current_at`. The writer answers stale or unchanged, so a price someone set since stays.
  - Rejected: a per-line "carried" marker column.
- **G2, where the kind comes from.**
  - Chosen: the kind comes from the matcher's own `lineFamily`.
  - Rejected: a second keyword list, which would drift from the first. Also rejected: holding such lines until a person picks the kind.
  - An unknown section keeps wine/bottle, because the row carries a `master_wine_id`.
- **G3, how Turkish words match.**
  - Chosen: fold the text first (case, accents, ı to i), then match whole words with optional Turkish endings.
  - Not hints: tatlı alone, yemek alone, balık, dürüm. A false kitchen line hides a drink, so the cheaper error was chosen.
- **G6, where the ı fold lives.**
  - Chosen: the fold is in `house-good-match.ts` only. The shared `wine-signature` fold keys stored hashes.
  - Rejected: changing the shared fold and re-hashing the library.
- **G5, how goods are matched.**
  - Chosen: index the goods by exact folded name. The match rules are unchanged.
  - Rejected: fuzzy or trigram matching, which would change what counts as the same good.
- **G7, where the price is parsed.**
  - Chosen: one parser, on the gateway. New optional `*_typed` fields carry the text.
  - Rejected: porting `parseMenuPrice` to the web, which makes two copies that drift. Also rejected: changing the type of the number fields, which the onboarding review step uses.
