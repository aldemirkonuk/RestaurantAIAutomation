## Built

1. **An uncosted order is unknown, not $0 (#1144).**
   - New `analytics/order-cost.ts` with `orderCostOrNull` and `UncostedOrdersError`.
   - A `purchase_spend` goal window that holds any uncosted order now refuses, and says how many orders have no cost.
   - Insights read the 180-day order bundle through `readWholeWindow`. While any order is uncosted, the whole purchasing family is withheld and reported as `spendWithheld`.
   - `INSIGHT_GENERATOR_VERSION` goes from 12 to 13. Rejected: an "at least" lower bound (unsafe for at_most goals) and silently dropping uncosted orders.
2. **pos_checks are read whole or refused (#1145).** Covers `PosHubService.getStatus`, `SaleRecordProducer.dayTotals` and `DevTruthService.asOf`.
   - The brief named `readByIds`, but these are date windows over unique ids, so the session used `readWholeWindow` (ADR 0292).
   - A sale-record day past `CHECK_CAP` (2,000) refuses.
   - A failed status read returns `unavailable: true` rather than a 503.
3. **#945's cost readers adopt readByIds (#1146 + #1147).**
   - #1146 copies `common/read-by-ids.ts` and its spec byte for byte from #1131 (checked with `cmp`).
   - #1147 adds `analytics/lot-costs-by-ids.ts`, `readLotCostsByIds`, which reads both views, the rollup and the agreed cost, by id in batches of 100. It is used by `AnalyticsService.loadInventory`, `AdvancedAnalyticsService.loadInventoryWithCost` and `MarginAdviceService.adviseHouse`.
   - A failed agreed-cost read now refuses. Before, it was logged and the wines read as unknown.
   - #945 itself is not edited.
   - The work was split into two PRs to stay under the 30K diff cap: #1147 is 29,344 B and #1146 is 6,092 B.
4. **Refresh and switch-restaurant leave the 10/min auth bucket (#1148).**
   - New `SESSION_RENEWAL_RATE_LIMIT` = 100/min, still keyed on IP + route.
   - Brute force is not a concern here: the refresh token is a signed JWT, verified before any database read. Guessing a valid one means forging the signature, so the request rate does not matter.
   - Login, oauth/google, reset-password and join stay at 10/min, and the spec now pins them.
   - Rejected alternatives: keep 10/min, reuse SESSION_READ, key the limit per token, or pick an arbitrary 30.
