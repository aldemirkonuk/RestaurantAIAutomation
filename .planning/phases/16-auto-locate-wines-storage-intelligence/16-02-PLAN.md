**Algorithm scoring (implement in service):**

Temperature preference map (parse location temperature string "55°F" → 55 via regex):
```
WINE_TEMP_PREFERENCES = {
  'red':       { ideal: 62, range: [58, 68] },
  'white':     { ideal: 52, range: [48, 56] },
  'sparkling': { ideal: 47, range: [43, 52] },
  'rosé':      { ideal: 52, range: [48, 56] },
  'rose':      { ideal: 52, range: [48, 56] },  // alternate spelling
  'dessert':   { ideal: 52, range: [48, 58] },
  'fortified': { ideal: 57, range: [54, 62] },
}
```

Score function per (wine, location) pair:
1. **Temperature score (0–40 points):** Parse location temperature. If no temperature: 20 points (neutral). If temperature in wine's range: 40 points. If within ±5°F of range: 20 points. If outside ±10°F: 0 points.
2. **Type grouping score (0–30 points):** Count how many wines of same primary_type are already proposed/assigned to this location. 0 wines same type: 0 pts, 1-3: 15 pts, 4+: 30 pts. This creates type clustering.
3. **Capacity score (0–20 points):** `availableSpace = location.capacity - location.current_count - alreadyProposedBottles`. If availableSpace >= wine.quantity: 20 pts. If availableSpace > 0 but < wine.quantity: 10 pts (partial fit). If 0: location is ineligible (skip).
4. **Accessibility score (0–10 points):** Bar Stock / bar-type locations get +10 for high-frequency types (sparkling, rosé). Cellar / main cellar locations get +5 for aged reds/desserts. Detect by `location_type` field or by name containing "bar" (case-insensitive).

**Assignment algorithm:**
1. Fetch all wines to assign: query `wine_location_mappings` for this restaurant → get all mapped wine_ids → then get their details from `master_wine_library`. If `clear_existing=true`, start fresh from all wines at location.
   
   **IMPORTANT**: The algorithm should work on wines that ARE in the restaurant's inventory. Since `master_wine_library` is global, look at existing `wine_location_mappings` for this restaurant OR accept the wine IDs from the request body (see below). The simplest approach: query all rows in `wine_location_mappings` where `restaurant_id = restaurantId` → get the wine_ids → fetch their details from `master_wine_library`.

   If there are NO existing mappings (common case when feature is first used), the endpoint should also accept an optional `wine_ids: string[]` in the request body. The frontend will pass all inventory item IDs when calling auto-locate for the first time.

2. Sort wines by score priority: wines with strongest temperature preferences first (sparkling, whites need cool temps more strictly than reds).

3. For each wine (sorted by priority):
   - Score against all locations with available capacity
   - Pick the location with highest score (score > 0 required)
   - Tentatively assign: decrement that location's `availableSpace` tracker in memory
   - If no location has score > 0 or all full: add wine to `unassigned` list with reason

4. Build response: `AutoLocateResponseDto`

5. If `dry_run=false`: upsert all proposed assignments into `wine_location_mappings` using the existing `assignWineToLocation` logic (batch upsert).

**Frontend hook:**
```typescript
export function useAutoLocate() {
  const { activeRestaurantId } = useAuth()
  const restaurantId = activeRestaurantId ?? ''
  const queryClient = useQueryClient()

  // Preview (dry_run=true)
  const previewMutation = useMutation({
    mutationFn: async (params: { wineIds?: string[]; strategy?: string }) => {
      const { data } = await apiClient.post(
        `/storage-locations/${restaurantId}/auto-locate`,
        { dry_run: true, strategy: params.strategy ?? 'type_grouped', wine_ids: params.wineIds }
      )
      return data as AutoLocateResponse
    }
  })

  // Confirm (dry_run=false)
  const confirmMutation = useMutation({
    mutationFn: async (params: { wineIds?: string[]; strategy?: string; clearExisting?: boolean }) => {
      const { data } = await apiClient.post(
        `/storage-locations/${restaurantId}/auto-locate`,
        { dry_run: false, strategy: params.strategy ?? 'type_grouped', wine_ids: params.wineIds, clear_existing: params.clearExisting ?? false }
      )
      return data as AutoLocateResponse
    },
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ['storageLocationMappings', restaurantId] })
      queryClient.invalidateQueries({ queryKey: ['storageLocations', restaurantId] })
      queryClient.invalidateQueries({ queryKey: ['winesAtLocation', restaurantId] })
    }
  })

  return {
    preview: previewMutation.mutate,
    confirm: confirmMutation.mutate,
    isPreviewing: previewMutation.isPending,
    isConfirming: confirmMutation.isPending,
    previewResult: previewMutation.data,
    previewError: previewMutation.error,
  }
}

}
```
