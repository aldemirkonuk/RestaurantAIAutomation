## Implementation Decisions

### D-01: Three-Layer Architecture (locked)

The research agent uses three layers executed in order per record. Each layer fills what it can;
subsequent layers only process remaining gaps.

```
Layer 1: Deterministic Inference Engine (zero cost, instant)
  └─ Query Phase 9 ontology: appellation → grape, region, sub_region
  └─ Producer normalization from existing master_wine_library data
  └─ Vintage plausibility from ontology vintage_rules
  └─ Confidence = 0.99 for deterministic fills
  └─ Estimated coverage: 30-40% of null fields at $0

Layer 2: Cascade LLM Enrichment (low cost, cached)
  └─ Model routing by field difficulty (D-02)
  └─ Semantic entity cache: producer-level + region-level + wine-level (D-04)
  └─ Batch queries by producer to reduce Serper calls
  └─ Estimated coverage: 40-50% of remaining nulls

Layer 3: Deep Research with Reflexion (higher cost, thorough)
  └─ Adaptive retry with plateau detection (D-03)
  └─ Multi-hop reasoning chains
  └─ Fetch-verify with Playwright for tier-A
  └─ Human escalation for unresolvable conflicts
  └─ Estimated coverage: 60-80% of remaining nulls
```

Combined target: 85-95% of all null fields filled.

### D-02: Model Cascade Strategy (locked — balanced-aggressive)

Find the middle ground between aggressive cost optimization and quality-first:

```python
def select_model(field_name: str, ontology_hint_conf: float, attempt: int) -> str:
    """
    Smart cascade routing per field difficulty.
    
    - Haiku ($0.0002/call): fields where ontology gives strong hints (conf > 0.7),
      basic categorization (color, primary_type, sweetness_level, is_blend)
    - Flash ($0.001/call): default for standard research fields (region, grape,
      tasting_notes, producer_bio, description, food_pairing)
    - Sonnet ($0.01/call): ONLY for:
      a) Obscure producers with no ontology match
      b) Fields that failed Flash extraction on prior attempt
      c) Complex blends (multiple grape varieties)
      d) Conflicting sources requiring nuanced judgment
    """
```

Target cost: ~$0.008-0.012/record average. Haiku handles ~40% of LLM calls,
Flash handles ~50%, Sonnet handles ~10%.

### D-03: Adaptive Retry with Plateau Detection (locked)

Option C — adaptive retry until confidence threshold met or cost cap hit — with
safety mechanisms to prevent burning money on non-progressing retries:

```python
MAX_REFLEXION_RETRIES = 3

def should_retry(attempt: int, prev_result: dict, curr_result: dict, field_name: str) -> bool:
    """
    Adaptive retry with early stopping:
    
    1. PLATEAU DETECTION: If attempt N produces the same extracted values
       as attempt N-1 (same value set after normalization) → STOP immediately.
       No new information = no point retrying.
    
    2. FIELD-LEVEL VERIFICATION LOCKING: Once a field value is fetch-verified
       (confirmed on source page), mark as "verified_locked" and EXCLUDE from
       future research rounds. Don't re-research what's already confirmed.
    
    3. NOVELTY THRESHOLD: Each retry must produce at least 1 new distinct value
       OR use a new search query strategy, otherwise STOP.
    
    4. COST GATE: If cumulative cost for this field exceeds
       BUDGET_PER_RECORD_MAX / len(target_fields), STOP for this field.
    
    5. REFLECTION: On retry, append to prompt:
       "Previous attempt extracted: {prev_values}. These did not pass verification.
        Try a different search angle or source type."
    """
```

This ensures every retry makes progress. Fields that are genuinely unfillable
get marked `research_exhausted` after max retries with no progress, preventing
future wasted spend.

### D-04: Hierarchical Entity Caching (locked — best ROI at all scales)

Three-tier caching strategy that scales from 1K to 1M+ wines:

```
Tier 1: Wine-level exact cache (hash of name+vintage+producer)
  └─ Prevents re-research of identical wines
  └─ Redis key: research:wine:{sha256(name|vintage|producer)}
  └─ TTL: 30 days

Tier 2: Producer-level entity cache (all research about a producer applies to their wines)
  └─ "Antinori" research → producer_country, producer_bio, typical regions
  └─ Redis key: research:producer:{normalized_producer_name}
  └─ TTL: 90 days (producer facts change rarely)
  └─ Handles 60-80% of cache hits at scale

Tier 3: Region-level rule cache (appellation rules from Phase 9 ontology)
  └─ Deterministic fields cached from DB on first access
  └─ In-memory LRU (bounded, max 2000 entries)
  └─ Populated by Layer 1 deterministic inference
```

**Scale behavior:**
- 1K wines: In-memory LRU sufficient, no Redis needed
- 10K wines: Redis cache kicks in, producer batching saves ~50% Serper calls
- 100K wines: Producer cache dominates (same 500 producers, many wines each)
- 1M+ wines: Pre-warm producer cache, Layer 1 handles 30-40% at $0

**Implementation:** Use Redis if available (REDIS_URL configured), fall back to
in-memory LRU with bounded size (max 5000 entries) for dev/test.

### D-05: Authority-Weighted Conflict Auto-Resolution (locked — safe SOTA)

Auto-resolve conflicts ONLY when accuracy is 100% guaranteed. Otherwise, escalate
to human queue.

```python
def resolve_conflict(candidates: list[dict], field_name: str) -> tuple[str, str]:
    """
    Returns (resolution: 'auto'|'human', reason: str)
    
    AUTO-RESOLVE (100% safe):
      1. Tier-A vs Tier-C: auto-accept Tier-A.
         Official/regulatory site vs random web → always trust official.
         REQUIRED: Tier-A value must be fetch-verified (confirmed on actual page).
      
      2. Tier-A vs Tier-B: auto-accept Tier-A IF fetch-verified.
         Official producer site vs trade press → trust official when confirmed.
      
      3. 2+ Tier-B sources agree vs 1 Tier-C disagrees: auto-accept B consensus.
         Two independent authoritative sources vs one random → safe.
    
    ALWAYS ESCALATE TO HUMAN:
      4. Tier-A vs Tier-A: two official sources disagree → human decides.
      5. Tier-B vs Tier-B: two trade sources disagree → human decides.
      6. No clear authority winner → human decides.
      7. Any field where auto-resolution confidence would be < 0.85 → human.
    
    SAFETY GATE: Auto-resolution requires fetch-verify confirmation on the
    winning value. If fetch-verify fails, escalate to human regardless of tier.
    """
```

### D-06: Critical Bug Fixes (locked — all 10 must be fixed)

| # | Bug | Fix |

| 1 | **Promotion selects `candidates[0]` regardless of tier** | Select the candidate whose URL earned the tier that `should_auto_promote` returned. If `A_single`, pick the tier-A candidate. If `B_dual`, pick the candidate from the highest-confidence extraction. |
| 2 | **Budget cap is Serper-only** | Sum ALL providers (serper + google + anthropic) in `_check_daily_budget`. Use `spend_logger` table, not hardcoded provider. |
| 3 | **`conflict_candidates` replaces instead of merges** | Deep-merge: `existing_conflicts.update(new_conflicts)` preserving conflicts on other fields from prior runs. |
| 4 | **`research_daily_budget_check_task` is a no-op** | Log result AND update `research_runs` with budget status. If budget exceeded, set a Redis flag `research:budget_exceeded:{date}` that `_research_async` checks. |
| 5 | **`time_to_fill_hours` never written** | Compute `(completed_at - started_at).total_seconds() / 3600` in `_write_results` and include in `research_run_stats` insert. |
| 6 | **`regression_rate` hard-coded to 0.0** | Track actual regressions: count fields where `check_regression_guard` returned False / total fields attempted. Store in `research_run_stats`. |
| 7 | **No auth on research routes** | Add `Depends(verify_admin_token)` to `POST /trigger`. Use the existing auth pattern from the project. At minimum, require `X-Admin-Key` header matching `ADMIN_API_KEY` env var. |
| 8 | **SSRF check has no DNS resolution** | Add `socket.getaddrinfo()` before fetch to resolve hostname, then check resolved IP against private ranges. Block `169.254.169.254` (cloud metadata). |
| 9 | **Metrics endpoints load entire tables** | Use Supabase aggregate RPCs or `COUNT`/`SUM`/`AVG` queries instead of `select("*")`. Paginate where aggregation isn't possible. |
| 10 | **In-process `_url_cache` unbounded growth** | Replace with `functools.lru_cache` or bounded dict (max 1000 entries, LRU eviction). |

### D-08: Layer 1 Scope (locked — appellation-derived fields only, Q1 answer: A)

Layer 1 deterministic inference is limited to:
- **Appellation → grape variety** (from `appellation_rules.required_grapes` — e.g., Brunello di Montalcino → Sangiovese 100%)
- **Appellation → region, sub_region, country** (from `wine_regions` hierarchy)
- **Vintage plausibility** (from `vintage_rules` — flag impossible vintages)
- **Producer normalization** (match against existing `master_wine_library` producer entries)

NOT included in Layer 1 (too fuzzy for deterministic inference):
- Style/body/sweetness inference from grape (requires fuzzy mapping)
- Tasting notes inference from region+grape (subjective)
- Price inference from any source (variable)

## Specific Ideas

### Ontology inference example (Layer 1)
```
Input: wine_name="Brunello di Montalcino 2019", appellation=NULL, grape_variety=NULL
Step 1: Fuzzy match "Brunello di Montalcino" against appellation_rules.appellation_name
Step 2: Found → required_grapes = [{"grape": "Sangiovese", "min_pct": 100}]
Step 3: region = "Tuscany", sub_region = "Montalcino", country = "Italy" (from wine_regions)
Output: 3 fields filled, confidence=0.99, source="ontology_inference", cost=$0.00
```

### Cascade routing example (Layer 2)
```
Field: color → Haiku (simple categorization, $0.0002)
Field: grape_variety → Flash (standard extraction, $0.001)
Field: tasting_notes for obscure Jura wine → Sonnet (complex, $0.01)
```

### Plateau detection example (Layer 3)
```
Attempt 1: Serper → "Cabernet Sauvignon" for grape_variety
Attempt 2 (reflection): Serper → "Cabernet Sauvignon" (same result)
→ PLATEAU DETECTED → STOP. Mark field as "research_exhausted" for this record.
```

### Producer-level batching example (Layer 2)
```
5 wines from "Antinori" need research:
  Instead of 5 × Serper queries for producer_country:
  → 1 query: "Antinori winery country origin" → Italy
  → Apply to all 5 wines from cache
  → 80% cost reduction for shared producer fields
```
