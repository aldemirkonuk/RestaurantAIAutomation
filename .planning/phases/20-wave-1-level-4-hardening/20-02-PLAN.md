<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Toast POS → POST /webhook | Untrusted external HTTPS post; must verify HMAC-SHA256 signature before any processing |
| POSIntegrationAgent → Toast API (polling) | Outbound HTTP to external service; response is untrusted JSON |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-02-01 | Spoofing | process_toast_webhook HMAC verification | mitigate | Phase 19 already fixed signature to use raw bytes + hmac.HMAC; idempotency check runs AFTER signature verification — forged replays are rejected at HMAC gate |
| T-20-02-02 | Tampering | order_guid used as idempotency key component | mitigate | Composite key f"{order_guid}:{event_type}" — attacker cannot replay different event_type for same order without processing being triggered (each type is independent) |
| T-20-02-03 | Information Disclosure | Toast API credentials in config | accept | Config loaded from environment variables, not hardcoded; Phase 22 adds secrets management |
| T-20-02-04 | Denial of Service | polling saga with 3 retries + backoff could be triggered by crafted empty-items webhook | mitigate | Signature verification required before saga trigger; duplicate webhook (same key) is deduplicated and does not retrigger saga |
| T-20-02-05 | Elevation of Privilege | compensate_saga publishes PartialOrderReceived to internal exchange | accept | Internal RabbitMQ exchange not externally accessible; event consumers validate payload schema |
</threat_model>
