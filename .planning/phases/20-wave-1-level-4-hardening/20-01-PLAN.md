<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| RabbitMQ → InventoryEngine | Incoming messages from message bus may be replayed or duplicated |
| InventoryEngine → Supabase | Stock write operations must be serialized (optimistic locking from Phase 19) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-01-01 | Tampering | message_id field in incoming message | mitigate | Idempotency check enforces exactly-once — attacker replaying message_id is deduplicated at DB level |
| T-20-01-02 | Repudiation | stock state changes | mitigate | Every handler calls `log_decision()` + `append_event()` — all changes immutably recorded in decision_log and event_store |
| T-20-01-03 | Denial of Service | event_store insert in hot path | accept | insert is best-effort; failure is logged but does not block stock update (exception caught in append_event) |
| T-20-01-04 | Elevation of Privilege | manual_correction handler accepts any manager_id | accept | Phase 21 scope — authentication/authorization enforced at API gateway, not agent level |
</threat_model>
