# Phase 28 — Plan 05: Retire 9-Step Wizard + Fix Post-Verify Redirect

## Objective
Complete the onboarding reform by:
1. Fixing the post-email-verify redirect to point to `/get-started`
2. Retiring the 9-step onboarding wizard gracefully (preserve POS step, remove duplicates)
3. Guarding `/get-started` against users who've already uploaded a menu

## Tasks

### Task 1: Fix VerifyEmail.tsx redirect

Find the success path in `apps/web/src/pages/VerifyEmail.tsx` where the user is redirected after
clicking the verification link.

Change:
```typescript
// Before
navigate('/onboarding')
// or
navigate('/')
```

To:
```typescript
// After — check if menu already uploaded (for re-verification flows)
const progress = await getOnboardingProgress()
if (progress?.menu_uploaded) {
  navigate('/')
} else {
  navigate('/get-started')
}
```

### Task 2: Guard /get-started against repeat visits

In `GetStarted.tsx`, add a mount-time check:
```typescript
const { progress } = useOnboardingProgress()

useEffect(() => {
  if (progress?.menu_uploaded) {
    navigate('/', { replace: true })
  }
}, [progress])
```

This ensures users who already uploaded a menu are never stuck on the page again.

### Task 3: Retire Onboarding.tsx

Replace the 9-step wizard body with a slim redirect page:
```tsx
// Onboarding.tsx — slim version
export default function Onboarding() {
  const navigate = useNavigate()

  return (
    <div className="min-h-screen flex flex-col items-center justify-center p-8">
      <Wine className="w-12 h-12 text-wine-600 mb-4" />
      <h1 className="text-2xl font-bold mb-2">Setup has moved</h1>
      <p className="text-gray-600 mb-6 text-center max-w-sm">
        Your setup checklist is now on the dashboard.
        If you want to connect your POS system, you can find it in Settings → Integrations.
      </p>
      <Button onClick={() => navigate('/')}>Go to Dashboard →</Button>
    </div>
  )
}
```

The existing `OnboardingContext.tsx` and `ONBOARDING_STEPS` are preserved (other components may
reference them). They are not deleted — just no longer the primary onboarding path.

### Task 4: Update App.tsx route order
Ensure `/get-started` is accessible to authenticated users who haven't yet been redirected:
```tsx
// These routes are accessible to any authenticated user
<Route path="/get-started" element={<GetStarted />} />
<Route path="/verify-email" element={<VerifyEmail />} />
<Route path="/onboarding" element={<Onboarding />} />
```
